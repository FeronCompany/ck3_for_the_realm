# 朝堂权力角逐（Court Struggle）系统设计

> 本文件是「朝堂权力角逐」系统的**唯一设计出处**。
> **修改任何相关脚本代码前先读本文件，改完代码后必须同步更新本文件。**
>
> 对应议题：议题 1（继任者之争）、议题 2（共治夺权）。
> 议题 3（异族异教）、议题 4（对外战争）已移出本次范围，未实现。

---

## 1. 目标与范围

### 1.1 设计目标

在**独立王国 / 帝国 / 霸权**级别政权内部，模拟一场围绕大位的持续权力角逐：

- **议题 1 — 继任者之争**：潜在继任者（子女/手足/继承顺位者）**自愿选择参与角逐**（上限 5 人），以「竞争力评分」排名，彼此排挤、拉拢支持者；势均力敌时爆发政变或内战。
- **议题 2 — 共治夺权**：君主因年老体衰或精神异常不能正常履职时，权臣与潜在继任者尝试获取共治权力乃至夺取大位；保皇派与拥立派围绕「权力天平」拉锯，双方以官位、契约为筹码争取支持者。

> **1.0 版重构核心**：继任者不再被动进入名单，而是**主动选择是否参与**。最高统治者、共治者与参与角逐的继任者同为可被支持的「权贵」，各自拥有支持者列表。GUI 移除配偶/姬妾栏与权臣/内阁栏，改为展示君主与共治者的支持者，继任者列表仅拉取参与角逐者（无人参与则占位）。story 面板可视化用 `character_list` 横向展示参与角逐的继任者头像。

### 1.2 准入条件（本节是唯一出处，§10 频率控制引用此处）

由 `ftr_court_struggle_valid_trigger` 统一判定，三条必须同时满足：

| 条件 | 实现 |
|---|---|
| 独立政权 | `is_independent_ruler = yes` |
| 等级 ≥ 王国 | `highest_held_title_tier >= tier_kingdom` |
| **主头衔存在继承顺位** | `primary_title = { any_title_heir = { always = yes } }`（**全面放宽**） |

附加限制：`is_ruler = yes`、未被囚禁、非战时、不在冷却期内。

> **1.0 版改动**：触发条件全面放宽。原先要求"候选人 ≥ 2 且君主衰弱/竞争者众多"，现只要主头衔继承顺位列表非空即触发。`ftr_court_should_activate_succession_trigger` 仅保留 valid + 非冷却判断。

### 1.3 触发入口与参与者

**Story cycle 的 `owner` 恒为在位君主**，君主是系统唯一持有者。

各身份的参与方式：

| 身份 | 参与方式 |
|---|---|
| 君主 | 决议（3 个）＋作为交互 recipient 被辅政/请愿/游说/支持 |
| **参与角逐的继任者** | 事件 0040 选择参与（+`ftr_court_participating` flag）→ 交互/事件 0015/政变/起兵 |
| **明确不参与者** | 事件 0040 选择不参与（+终身 `ftr_court_declined_contest` flag，防止被他人主动支持） |
| 权臣 | 辅政、游说、请愿共治、废黜昏君（0018） |
| 无地廷臣 | **仅事件路径**（0014 站队、0015 择主起兵）——无地者不能使用决议、不能主动发起交互 |
| 其它封臣 | 事件 0014 站队、被游说、战时响应召集 |

> **1.0 版改动（参与角逐系统）**：故事启动后自动触发事件 0040 询问利益相关方。
> - **血缘继承**：询问君主子女 / 兄弟姐妹（按性别继承法 `ftr_court_gender_succession_allows_trigger` 过滤）。
> - **选举继承**：按主头衔继承顺位依次询问。
> - 参与上限 5 人；已明确不参与者（`ftr_court_declined_contest`）不再询问。
> - 定期（30-60 天随机）刷新 `ftr_court_launch_participation_asks_effect`：移除失能/被剥夺继承权/被囚禁/死亡的参与者，并给未表态且未拒绝的潜在继承人一次机会。

## 2. 技术选型：为什么用故事循环，不用局势

| 方案 | 结论 | 理由 |
|---|---|---|
| **局势 Situation** | ❌ 否决 | `sub_regions` 必须绑定**静态地理区域**（`geographical_regions`，上限 255 且不可重叠）。而需求是「每个独立王国各自内部」的权力斗争——王国边界会变、会灭亡、全球同时存在几十个。局势无法按政治实体开实例。中原王朝循环能用，是因为它是全地图唯一且绑死在中国地区。 |
| **故事循环 Story Cycle** | ✅ 采用 | 绑角色（`owner` = 君主）、可多实例（owner 维度隔离 → 全球每个王国各持一个实例）、`on_owner_death` 天然对应「君主驾崩重洗牌」、`visualization` 原生支持角色名单与拉锯条。 |
| **纯脚本状态机** | ❌ 否决 | 无原生面板，需自建 GUI；无生命周期管理，清理易泄漏。 |

**子议题驱动模型**（重要）：议题 1 与议题 2 **不设独立开关变量**，共存于同一个 story 实例，各自由独立信号驱动：

- 议题 1 由**阶段号** `ftr_court_phase`（0–3，由竞争者数量与前两名分差推导）驱动
- 议题 2 由**权力天平** `ftr_court_regency_swing`（−100 ~ +100）驱动

两议题共享候选池、支持者记账与政治资源，拆成两个容器会导致数据同步困难与面板割裂。

### 2.1 关键接口（原版实测确认）

| 用途 | 接口 |
|---|---|
| 启动故事 | `create_story = <key>`（角色域执行，owner = 当前角色） |
| 结束故事 | `end_story = yes` |
| 防重复 | `any_owned_story = { type = <key> }` |
| 排序遍历列表 | `ordered_in_list = { list = X  order_by = <script value 或数值> }`（`prestige`、`max_military_strength` 均可直接作 order_by） |
| 「有兵」判定 | `max_military_strength > 0`（**没有** `has_army` 这个 trigger） |
| 列表长度 | `list_size:<list_name>`（用于 `set_variable`） |
| 无地头衔 | `create_dynamic_title` + `set_landless_title` + `set_delete_on_destroy` |
| 剥夺继承权 | `disinherit_effect = { DISINHERITOR = <君主scope> }`（**在被剥夺者域执行**，参数指向剥夺者） |
| 停战协定 | `add_truce_both_ways = { character = X  days = N  war = W  result = R }` |
| 宣战 | `start_war = { casus_belli = X  target = Y }` |
| 拉人入战 | `scope:war = { add_attacker / add_defender = scope:X }` |
| 内阁实授 | `assign_appropriate_councillor_position_effect = { NEW_COUNCILLOR = X }`（官方效果：按最高技能分派 + 四级 fallback + 现任可解雇检查） |
| 强权封臣 | `is_powerful_vassal = yes`（裸用；`is_powerful_vassal_of = X` 是另一变体） |

> ⚠ **已修正的文档错误**：`document/09-故事循环与局势.md` 与 `document/16` 中原写作 `start_story = { }`，**原版不存在此 effect**，正确写法是 `create_story = <key>`。

## 3. 系统架构

### 3.1 Story 容器结构

单一 story cycle 类型 `ftr_court_struggle`，挂在最高统治者身上：

```
ftr_court_struggle (story cycle, owner = 最高统治者)
├── on_setup        初始化变量、启动参与询问（0040）
├── effect_group ①  年度维护：刷新参与者、拉锯自然回落、阶段迁移
├── effect_group ①' 参与者刷新（30-60 天随机）：移除失能/被剥夺者，给未表态者机会
├── effect_group ②  危机脉冲（20%/年）：
│   ├── 0005 危机事件（君主抉择）
│   ├── 0014 询问 1 名未站队者（封臣或廷臣）
│   ├── 0015 询问竞争力最高的竞争者是否起兵
│   └── 0018 天平≥+75 且君主失能 → 询问最强势力是否废黜昏君
├── effect_group ③  对立脉冲（14%/年）：0003 + 0014
├── effect_group ④  潜伏脉冲（8%/两年）：0001
├── on_owner_death  驾崩 → end_story（清理统一交给 on_end）
└── on_end          清理临时头衔、清除变量与 flag
```

> **事件触发必须写成 `owner = { trigger_event = ... }`**：`trigger_event` 的 root 取当前作用域，而事件是 `character_event`；直接调用会让 root 变成故事本体。
> 例外：0018 的 root 应是权臣本人，故在 `ordered_in_list` 内对 `scope:ftr_court_usurper` 直接触发。

### 3.2 阶段定义（议题 1）

| 值 | 阶段 | 判定条件（由 `ftr_court_update_phase_effect` 统一定档） |
|---|---|---|
| 0 | dormant | 竞争者数 < 2 |
| 1 | simmering | 竞争者数 ≥ 2 |
| 2 | contested | 前两名评分差 ≤ `ftr_court_contested_gap_value`(20) |
| 3 | crisis | 评分差 ≤ `ftr_court_crisis_gap_value`(8) **且** 君主衰弱 |

### 3.3 on_action 调度（`ftr_court_on_actions.txt`）

| 钩子 | 挂载点 | 作用 |
|---|---|---|
| `ftr_court_try_start_on_action` | `random_yearly_everyone_pulse` | 为符合条件的新君建立故事（准入见 §1.2） |
| `ftr_court_on_child_born_on_action` | `on_birth_child` | 刷新父母所在朝堂的候选池 |
| `ftr_court_validate_on_action` | `random_yearly_everyone_pulse` | 政权失效（被征服/降级/绝嗣）时收场兜底 |
| `ftr_court_on_council_promise_check_on_action` | `on_death` | 自然继承路径：`scope:primary_heir` 欠账时安排内阁承诺提醒（0016） |

设计原则：story 建立后，年度维护完全交给 effect_group；on_action 只负责**准入创建、增量刷新、收场、继承检查**。君主驾崩后新君是否重启角逐由下一年度检查处理——刻意避开继承结算的时序风险。

### 3.4 面板可视化（story `visualization`）

| 组件 | 绑定 | 说明 |
|---|---|---|
| `character_list` | `ftr_court_participant_list` | 参与角逐者名单（最多五人） |
| `tug_of_war_counter` | `ftr_court_regency_swing` | 权力天平（0 君权稳固 ↔ 100 共治得势） |
| `basic_counter` | `ftr_court_candidate_count` | 参与角逐者人数（0–5） |
| `custom_string_key` | `FTR_COURT_STRINGS` | 面板说明文案 |

危机阶段图标切换为征服者剑图标，其余阶段用宫廷政治图标。

### 3.5 窗口数据同步（个人变量列表方案）

为避免 story 域变量读取问题，参与者与支持者数据**主存储放在角色（权贵）的个人变量列表上**，GUI 与 story 都从角色身上获取：

- **参与者列表主存储**：最高统治者（`story_owner`）身上的 `ftr_court_claimants` 变量列表。角色参与时（事件 0040）直接把参与者写入该列表，并同步到 story 的 `ftr_court_participant_list`。
- **支持者列表主存储**：各权贵（君主 / 共治者 / 参与角逐者）身上的 `ftr_court_supporters` 变量列表。角色站队时（`back_claimant`）把自己加入被支持者的 `ftr_court_supporters`；退出 / 转投时从旧主的 `ftr_court_supporters` 移除自己。

**GUI 同步链路**（`ftr_court_sync_ui_data`）：
1. `ftr_court_sync_ui_from_story_effect`：从最高统治者 `ftr_court_claimants` 复制到玩家域 `ftr_court_ui_claimants`，并计算 `ftr_court_ui_count`。
2. `ftr_court_sync_courtiers_effect`：从各权贵的 `ftr_court_supporters` 复制到玩家域 `ftr_court_ui_monarch_backers` / `ftr_court_ui_diarch_backers`，以及各参与者的 `ftr_court_heir_backers`。
3. **GUI**：读取玩家域 `ftr_court_ui_claimants` / `ftr_court_ui_monarch_backers` / `ftr_court_ui_diarch_backers`，以及各参与者身上的 `ftr_court_heir_backers`。

任何角色（君主 / 封臣 / 廷臣）打开窗口时，都能从对应权贵的个人变量列表读取到最新数据。

## 4. 数据模型

### 4.1 Story 域变量

| 变量 | 类型 | 用途 |
|---|---|---|
| `ftr_court_phase` | int | 0–3 阶段号 |
| `ftr_court_candidate_count` | int | 参与角逐人数（= 参与者数） |
| **`ftr_court_participant_list`** | char list | **参与角逐者名单（由最高统治者个人列表定期同步而来，供 story 逻辑/可视化使用）** |
| `ftr_court_participant_count` | int | 参与角逐者人数（上限 5） |
| `ftr_court_regency_swing` | int | 权力天平 |
| `ftr_court_swing_amount` | int | 移轴效果参数（临时，调用方设置、调用后清理） |

> **1.0 版改动**：`ftr_court_claimant_list` 由"按竞争力评分取前五名"改为 `ftr_court_participant_list`（仅收录**选择参与角逐**的继任者）。**新方案**：参与者列表**主存储放在最高统治者个人变量 `ftr_court_claimants` 上**（角色身上），story 的 `ftr_court_participant_list` 由故事定期从最高统治者列表同步而来（`ftr_court_update_candidates_effect`），避免 story 域变量读取问题。候选池/评分排序逻辑相应移除，评分仅用于展示排名（`ftr_court_save_ranked_claimants_effect` 仍按评分排序固定选项）。

### 4.2 角色域变量

| 变量 | 挂在谁身上 | 用途 |
|---|---|---|
| `ftr_claim_strength` | 参与角逐者 | 竞争力评分 |
| `ftr_court_backer_of` | 支持者 | 我支持谁（站队记账） |
| **`ftr_court_claimants`** | **最高统治者** | **参与角逐者列表（新方案主存储）** |
| **`ftr_court_supporters`** | **权贵（君主/共治者/参与者）** | **各权贵的支持者列表（新方案主存储）** |
| **`ftr_court_support_count`** | **权贵（君主/共治者/参与者）** | 获得的支持者数（= `ftr_court_supporters` 列表大小） |
| `ftr_court_owes_council` | **承诺者** | 欠下的内阁席位笔数（0016/0017 触发依据） |
| `ftr_court_promise_council` / `ftr_court_promise_contract` | **被承诺者** | 承诺类型 |
| `ftr_court_promised_by` | **被承诺者** | 谁向我承诺过 |
| `ftr_court_temp_duchy` | 起兵者 | 临时公国引用（战后回收） |

> 记账约定：**站队记在支持者身上（`ftr_court_backer_of`），支持者名单记在被支持权贵身上（`ftr_court_supporters`）**——前者标识支持关系，后者作为主存储供 GUI 直接读取。承诺记在被承诺者身上。
> **1.0 版改动**：参与者列表主存储由 story 域改为**最高统治者个人变量 `ftr_court_claimants`**；支持者列表改为**各权贵个人变量 `ftr_court_supporters`**（原 `ftr_court_backer_count` 计数改为读取列表大小 `ftr_court_support_count`），君主与共治者也各有支持者列表。

### 4.4 竞争力评分（议题 1 的排名依据）

**不使用真实继承顺位**。原版无任何「顺位序号」触发器（`heir_order` / `succession_position` / `inheritance_order` 全库 0 命中），只有 `every_heir` 集合遍历。故改用**竞争力评分**排名：

`ftr_court_claim_strength_value` 构成（系数集中在 `ftr_court_struggle_values.txt`）：

| 维度 | 分值 |
|---|---|
| 年龄 | 成年 +20，青壮年(16–45) +10，老年 −10 |
| 能力 | 五维平均值 × 2 |
| 特质 | ambitious +30、genius +20、brave +10；content −30、craven −20、incapable −100、lunatic −25 等 |
| 实力身份 | 有地 +25、内阁 +15、共治者 +40、配偶 +10、法定继承人 +25 |
| 君主好感 | ≥50 → +15；≥0 → +5；<0 → −10 |
| 支持者 | 每人 +5 |

最终 `max = 0` 防负分。候选人来源：君主的 `every_heir` + `every_child` + `every_sibling`，经 `ftr_court_claimant_valid_trigger` 过滤（存活、成年、未被囚禁、非 incapable、同宗族、非修道者）。

> 选举制与均分继承制下「顺位」本就模糊，评分反而更贴合玩家直觉。

## 5. 议题 2：共治夺权

### 5.1 权力天平（`ftr_court_regency_swing`）

| 值 | 含义 |
|---|---|
| −100 | 君权稳固（区间下限） |
| −40 | 触发「辅政稳固」判定 |
| 0 | 中性 |
| +40 | 触发「共治请愿」门槛 |
| +75 | 触发「废黜昏君」窗口 |

**变动来源汇总**（所有路径最终都经过 `ftr_court_shift_swing_effect`，该效果按 `ftr_court_swing_amount` 移动并夹紧区间）：

| 来源 | 幅度 | 说明 |
|---|---|---|
| 辅政交互（`assist_monarch`） | −8 | 有地权臣尽心王事 |
| 游说·劝忠（`lobby`） | −8 | 封臣互劝效忠君主 |
| 游说·劝进（`lobby`） | +8 | 封臣互劝支持共治 |

### 5.2 政治承诺（筹码机制）

许诺类交互（许官位 / 许宽免）在 `on_accept` 时建立双端记账（见 §4.2），继承后兑现：

**内阁席位 —— 三段式兑现链**：

```
许诺（记账：承诺者 owes_council +1；被承诺者记 promise_council + promised_by）
    │
继位（双路径全覆盖）
    ├─ 夺位 → usurp effect 尾部安排提醒
    └─ 自然继承 → on_death 检查 scope:primary_heir 欠账
    │
0016 首次提醒（继承后 3-7 日随机延迟 ← 错开多笔承诺，避免密集弹窗）
    ├─ a. 立刻授予 → 按最高技能实授 → 清账 → 若还有欠账串行下一个（5-15 日间隔）
    └─ b. 推迟一次 → 180-360 日随机延迟 → 0017
                        ├─ a. 授予 → 清账 → 串行
                        └─ b. 完全拒绝 → 背信好感 + 新君声望 −150 → 清账 → 串行
```

- **实授**：复用官方 `assign_appropriate_councillor_position_effect`（首选职位按最高技能，四级 fallback，现任可解雇检查）；非封臣承诺对象先 `add_courtier` 拉入宫廷
- **防呆**：0016/0017 均有欠账存在性检查——欠账已被其它途径兑现则事件**静默取消**；推迟不销账，只有授予/拒绝清账 → 结构上杜绝无限推迟；0017 无推迟选项
- **债务继承**：新君继承**存活者**的承诺。若旧竞争者在清算中被尽数处决，其生前许下的承诺一并作废（见 §8 事件 0011.b）

**契约放宽**：由 `ftr_court_fulfill_promises_effect` 以 `ftr_court_promised_contract_modifier` 兑现。该效果仅在清算事件 0011.a（赦免兑现）被调用——**新君选择清算或留地监视时契约承诺不自动兑现**。

### 5.3 夺位路径（议题 2 的三处出口）

| 路径 | 入口 | 适用 |
|---|---|---|
| **宫廷政变（0018.a）** | 天平 ≥ +75 且君主失能 → 危机脉冲询问朝堂最强势力（按兵力排序）→ 立即 `ftr_court_usurp_throne_effect`（夺位 + 囚禁 + 0010 清算链） | 全政体；**无需战争** |
| **密谋（0015.b）** | 危机脉冲询问竞争者 → `start_scheme = coup` | 行政制限定（密谋不要求领地，是**无地竞争者**的夺位路径） |
| **内战（0012.a / 0015.a）** | 竞争者起兵 → CB `ftr_succession_war` | 全政体；无地者先建临时公国（§6.2） |

`ftr_court_can_attempt_usurp_trigger`（+75 且失能）是 0018 的触发依据。

**usurp 效果统一收尾**（`ftr_court_usurp_throne_effect`，两条夺位路径共用）：夺取主头衔 → 囚禁旧君 → 排清算事件 0010 → 安排内阁承诺提醒 → 新君冷却 5 年 → 朝堂通报「大位易主」→ **旧君名下 story `end_story`**（旧君尚存但已失位，story 不会自行转移；新君是否重启角逐由下一年度准入检查判定）。

## 6. 战争：继位内战

### 6.1 CB 设计（`ftr_succession_war`，组 `ftr_civil_war`）

| 参数 | 取值 | 说明 |
|---|---|---|
| `target_titles` | `none` | 目标是整个政权而非某个头衔 |
| `landless_attacker_needs_armies` | `no` | 无地皇子不会因无兵自动判负 |
| `ai_only_against_liege` | `yes` | 仅封臣对宗主 |
| **`white_peace_possible`** | **`no`** | **造反不能白和平（§6.4）** |
| `on_primary_attacker_death` | `inherit_faction` | 主攻方死亡后阵营不崩盘 |
| `cost` | 威望 350 | 发动门槛 |
| `allowed_against_character` | 封臣对宗主 **或** 无地同宗持临时公国 | 无地者不是封臣，需第二分支 |

### 6.2 临时公国（无地竞争者）

**关键认知：无地角色无法宣战。** `landless_attacker_needs_armies = no` 只解决"宣战后无兵自动判负"，不解决"宣战入口不存在"。因此临时公国必须在**宣战之前**创建。

**两段式创建时机**：

| 阶段 | 位置 | 说明 |
|---|---|---|
| **预建（主路径）** | `ftr_court_prepare_rebellion_effect`（事件 0012.a / 0015.a 调用） | 无地者先建临时公国 → 立即 `start_war`，一体完成 |
| 兜底 | CB `on_declaration` | 仅当无地且未预建时补建，防路径遗漏 |

创建内容（`ftr_court_create_temp_duchy_effect`）：`create_dynamic_title`（tier = duchy，名 `FTR_COURT_TEMP_DUCHY_NAME`）→ `set_landless_title` / `set_destroy_on_succession` / `set_delete_on_destroy` / `set_no_automatic_claims` → 首都取王国境内随机伯爵领 → `change_title_holder` → 记入 `ftr_court_temp_duchy`。

**回收**：`on_victory` / `on_defeat` / `on_white_peace` / `on_invalidated` **四处全部销毁**，不论战争结果；另有 story 清理兜底扫描。

### 6.3 支持者响应

站队时记 `ftr_court_backer_of`，宣战时自动召集（均以 `is_participant_in_war` 查重）：

- **叛乱方**：`ftr_court_call_backers_to_war_effect` → 站队对象 = 起兵者且有地者 → `add_attacker`
- **保皇派**：`ftr_court_call_loyalists_to_war_effect` → 未站队或站队对象非起兵者、且对君主好感 ≥ 0 → `add_defender`

### 6.4 造反不能白和平（核心规则）

**叛乱只有三种结局：胜、败、战争失效。不存在「打完握手言和」。**

| 结局 | 处理 |
|---|---|
| **胜利** `on_victory` | `ftr_court_usurp_throne_effect`（夺位 + 囚禁 + 清算链 0010→0011→0012 + 冷却 + 收场） |
| **失败** `on_defeat` | 剥夺继承权 + 声望 −300 / 虔诚 −100 + **双向停战 1825 天** + 事件 0013（君主定夺：终身监禁 / 流放 / 处死 / 宽恕）；君主侧加 5 年冷却 |
| **失效** `on_invalidated` | 仅回收临时头衔，不追究（失效多为目标死亡等意外） |
| ~~白和平~~ | 不可达。`on_white_peace` 保留为**安全兜底**：万一引擎异常路径触发，按失败同等代价处理 |

> **设计意图**：叛乱是押上性命的豪赌。允许白和平会让「看形势不妙就收兵」成为无风险策略，继位之争将退化为例行公事。
> **已知副作用（接受）**：内战打到一方彻底崩溃为止，可能使国家长期虚弱——这是叛乱应有的代价。
