# 朝堂权力角逐（Court Struggle）系统设计

> 本文件是「朝堂权力角逐」系统的**唯一设计出处**。
> **修改任何相关脚本代码前先读本文件，改完代码后必须同步更新本文件。**
>
> 对应议题：议题 1（继任者之争）、议题 2（共治夺权）。
> 议题 3（异族异教）、议题 4（对外战争）已移出本次范围，未实现。

---

## 1. 目标与范围

### 1.1 设计目标

在**独立王国 / 帝国 / 霸权**级别政权内部，模拟一场围绕大位的持续权力角逐：

- **议题 1 — 继任者之争**：潜在继任者（子女/手足/继承顺位者）**自愿选择参与角逐**（上限 5 人），以「竞争力评分」排名，彼此排挤、拉拢支持者；势均力敌时爆发政变或内战。
- **议题 2 — 共治夺权**：君主因年老体衰或精神异常不能正常履职时，权臣与潜在继任者尝试获取共治权力乃至夺取大位；保皇派与拥立派围绕「权力天平」拉锯，双方以官位、契约为筹码争取支持者。

**设计核心**：继任者**主动选择是否参与**角逐。最高统治者、共治者与参与角逐的继任者同为可被支持的「权贵」，各自拥有支持者列表。GUI 展示君主与共治者的支持者，继任者列表仅拉取参与角逐者（无人参与则占位）。story 面板可视化用 `character_list` 横向展示参与角逐的继任者头像。

### 1.2 准入条件（本节是唯一出处，§10 频率控制引用此处）

由 `ftr_court_struggle_valid_trigger` 统一判定，三条必须同时满足：

| 条件 | 实现 |
|---|---|
| 独立政权 | `is_independent_ruler = yes` |
| 等级 ≥ 王国 | `highest_held_title_tier >= tier_kingdom` |
| **主头衔存在继承顺位** | `primary_title = { any_title_heir = { always = yes } }` |

附加限制：`is_ruler = yes`、未被囚禁、非战时、不在冷却期内。

准入判定（`ftr_court_struggle_valid_trigger` + `ftr_court_should_activate_succession_trigger`）只要求主头衔继承顺位列表非空即触发，无需候选人达标或君主衰弱/竞争者众多。

### 1.3 触发入口与参与者

**Story cycle 的 `owner` 恒为在位君主**，君主是系统唯一持有者。

各身份的参与方式：

| 身份 | 参与方式 |
|---|---|
| 君主 | 作为交互 recipient 被辅政/请愿/游说/支持 |
| **参与角逐的继任者** | 事件 0040 选择参与（+`ftr_court_participating` flag）→ 交互/事件 0015/政变/起兵 |
| **明确不参与者** | 事件 0040 选择不参与（+终身 `ftr_court_declined_contest` flag，防止被他人主动支持） |
| 权臣 | 辅政、游说、请愿共治、废黜昏君（0018） |
| 无地廷臣 | **仅事件路径**（0014 站队、0015 择主起兵）——无地者不能主动发起交互 |
| 其它封臣 | 事件 0014 站队、被游说、战时响应召集 |

故事启动后自动触发事件 0040 询问利益相关方是否参与角逐：
- **血缘继承**：询问君主子女 / 兄弟姐妹（按性别继承法 `ftr_court_gender_succession_allows_trigger` 过滤）。
- **选举继承**：按主头衔继承顺位依次询问。
- 参与上限 5 人；已明确不参与者（`ftr_court_declined_contest`）不再询问。
- 定期（30-60 天随机）刷新 `ftr_court_launch_participation_asks_effect`：给未表态且未拒绝的潜在继承人一次选择机会。

## 2. 技术选型：为什么用故事循环，不用局势

| 方案 | 结论 | 理由 |
|---|---|---|
| **局势 Situation** | ❌ 否决 | `sub_regions` 必须绑定**静态地理区域**（`geographical_regions`，上限 255 且不可重叠）。而需求是「每个独立王国各自内部」的权力斗争——王国边界会变、会灭亡、全球同时存在几十个。局势无法按政治实体开实例。中原王朝循环能用，是因为它是全地图唯一且绑死在中国地区。 |
| **故事循环 Story Cycle** | ✅ 采用 | 绑角色（`owner` = 君主）、可多实例（owner 维度隔离 → 全球每个王国各持一个实例）、`on_owner_death` 天然对应「君主驾崩重洗牌」、`visualization` 原生支持角色名单与拉锯条。 |
| **纯脚本状态机** | ❌ 否决 | 无原生面板，需自建 GUI；无生命周期管理，清理易泄漏。 |

**子议题驱动模型**（重要）：议题 1 与议题 2 **不设独立开关变量**，共存于同一个 story 实例，各自由独立信号驱动：

- 议题 1 由**阶段号** `ftr_court_phase`（0–3，由竞争者数量与前两名分差推导）驱动
- 议题 2 由**权力天平** `ftr_court_regency_swing`（−100 ~ +100）驱动

两议题共享参与角逐者、支持者记账与政治资源，拆成两个容器会导致数据同步困难与面板割裂。

### 2.1 关键接口（原版实测确认）

| 用途 | 接口 |
|---|---|
| 启动故事 | `create_story = <key>`（角色域执行，owner = 当前角色） |
| 结束故事 | `end_story = yes` |
| 防重复 | `any_owned_story = { type = <key> }` |
| 排序遍历列表 | `ordered_in_list = { list = X  order_by = <script value 或数值> }`（`prestige`、`max_military_strength` 均可直接作 order_by） |
| 「有兵」判定 | `max_military_strength > 0`（**没有** `has_army` 这个 trigger） |
| 列表长度 | `list_size:<list_name>`（用于 `set_variable`） |
| 无地头衔 | `create_dynamic_title` + `set_landless_title` + `set_delete_on_destroy` |
| 剥夺继承权 | `disinherit_effect = { DISINHERITOR = <君主scope> }`（**在被剥夺者域执行**，参数指向剥夺者） |
| 停战协定 | `add_truce_both_ways = { character = X  days = N  war = W  result = R }` |
| 宣战 | `start_war = { casus_belli = X  target = Y }` |
| 拉人入战 | `scope:war = { add_attacker / add_defender = scope:X }` |
| 内阁实授 | `assign_appropriate_councillor_position_effect = { NEW_COUNCILLOR = X }`（官方效果：按最高技能分派 + 四级 fallback + 现任可解雇检查） |
| 强权封臣 | `is_powerful_vassal = yes`（裸用；`is_powerful_vassal_of = X` 是另一变体） |

> ⚠ **接口说明**：启动故事的正确写法是 `create_story = <key>`（原版无 `start_story` 这一 effect）。

## 3. 系统架构

### 3.1 Story 容器结构

单一 story cycle 类型 `ftr_court_struggle`，挂在最高统治者身上：

```
ftr_court_struggle (story cycle, owner = 最高统治者)
├── on_setup        初始化变量、启动参与询问（0040）
├── effect_group ①  年度维护：拉锯自然回落
├── effect_group ①' 参与者询问刷新（30-60 天随机）：给未表态且未拒绝的潜在继承人一次机会
├── effect_group ②  危机脉冲（20%/年）：
│   ├── 0005 危机事件（君主抉择）
│   ├── 0014 询问 1 名未站队者（封臣或廷臣）
│   ├── 0015 询问竞争力最高的竞争者是否起兵
│   └── 0018 天平≥+75 且君主失能 → 询问最强势力是否废黜昏君
├── effect_group ③  对立脉冲（14%/年）：0003 + 0014
├── effect_group ④  潜伏脉冲（8%/两年）：0001
├── on_owner_death  驾崩 → end_story（清理统一交给 on_end）
└── on_end          清理临时头衔、清除变量与 flag
```

> **事件触发必须写成 `owner = { trigger_event = ... }`**：`trigger_event` 的 root 取当前作用域，而事件是 `character_event`；直接调用会让 root 变成故事本体。
> 例外：0018 的 root 应是权臣本人，故在 `ordered_in_list` 内对 `scope:ftr_court_usurper` 直接触发。

### 3.2 阶段定义（议题 1）

| 值 | 阶段 | 判定条件（由 `ftr_court_update_phase_effect` 统一定档） |
|---|---|---|
| 0 | dormant | 竞争者数 < 2 |
| 1 | simmering | 竞争者数 ≥ 2 |
| 2 | contested | 前两名评分差 ≤ `ftr_court_contested_gap_value`(20) |
| 3 | crisis | 评分差 ≤ `ftr_court_crisis_gap_value`(8) **且** 君主衰弱 |

### 3.3 on_action 调度（`ftr_court_on_actions.txt`）

| 钩子 | 挂载点 | 作用 |
|---|---|---|
| `ftr_court_try_start_on_action` | `random_yearly_everyone_pulse` | 为符合条件的新君建立故事（准入见 §1.2） |
| `ftr_court_validate_on_action` | `random_yearly_everyone_pulse` | 政权失效（被征服/降级/绝嗣）时收场兜底 |
| `ftr_court_on_council_promise_check_on_action` | `on_death` | 自然继承路径：`scope:primary_heir` 欠账时安排内阁承诺提醒（0016） |

设计原则：story 建立后，年度维护完全交给 effect_group；on_action 只负责**准入创建、收场、继承检查**。君主驾崩后新君是否重启角逐由下一年度检查处理——刻意避开继承结算的时序风险。

### 3.4 面板可视化（story `visualization`）

| 组件 | 绑定 | 说明 |
|---|---|---|
| `character_list` | `ftr_court_participant_list` | 参与角逐者名单（最多五人） |
| `tug_of_war_counter` | `ftr_court_regency_swing` | 权力天平（0 君权稳固 ↔ 100 共治得势） |
| `basic_counter` | `ftr_court_candidate_count` | 参与角逐者人数（0–5） |
| `custom_string_key` | `FTR_COURT_STRINGS` | 面板说明文案 |

危机阶段图标切换为征服者剑图标，其余阶段用宫廷政治图标。

### 3.5 窗口数据同步（个人变量列表方案）

为避免 story 域变量读取问题，参与者与支持者数据**主存储放在角色（权贵）的个人变量列表上**，GUI 与 story 都从角色身上获取：

- **参与者列表主存储**：最高统治者（`story_owner`）身上的 `ftr_court_claimants` 变量列表。角色参与时（事件 0040）直接把参与者写入该列表，并同步到 story 的 `ftr_court_participant_list`（供 story 逻辑与侧栏可视化使用）。无定期同步逻辑。
- **支持者列表主存储**：各权贵（君主 / 共治者 / 参与角逐者）身上的 `ftr_court_supporters` 变量列表。角色站队时（`back_claimant`）把自己加入被支持者的 `ftr_court_supporters`；退出 / 转投时从旧主的 `ftr_court_supporters` 移除自己。

**GUI 同步链路**（`ftr_court_sync_ui_data`）：
1. `ftr_court_sync_ui_from_story_effect`：从最高统治者 `ftr_court_claimants` 复制到玩家域 `ftr_court_ui_claimants`，并计算 `ftr_court_ui_count`。
2. `ftr_court_sync_courtiers_effect`：从各权贵的 `ftr_court_supporters` 复制到玩家域 `ftr_court_ui_monarch_backers` / `ftr_court_ui_diarch_backers`，以及各参与者的 `ftr_court_heir_backers`。
3. **GUI**：读取玩家域 `ftr_court_ui_claimants` / `ftr_court_ui_monarch_backers` / `ftr_court_ui_diarch_backers`，以及各参与者身上的 `ftr_court_heir_backers`。

任何角色（君主 / 封臣 / 廷臣）打开窗口时，都能从对应权贵的个人变量列表读取到最新数据。

## 4. 数据模型

### 4.1 Story 域变量

| 变量 | 类型 | 用途 |
|---|---|---|
| `ftr_court_phase` | int | 0–3 阶段号 |
| `ftr_court_candidate_count` | int | 参与角逐人数（= 参与者数） |
| **`ftr_court_participant_list`** | char list | **参与角逐者名单（由参与事件直接写入，供 story 逻辑/可视化使用）** |
| `ftr_court_participant_count` | int | 参与角逐者人数（上限 5） |
| `ftr_court_regency_swing` | int | 权力天平 |
| `ftr_court_swing_amount` | int | 移轴效果参数（临时，调用方设置、调用后清理） |

`ftr_court_participant_list` 仅收录**主动选择参与角逐**的继任者，参与者主存储放于最高统治者个人变量 `ftr_court_claimants`，story 的 `ftr_court_participant_list` 由参与事件（0040）直接写入、无定期同步，以规避 story 域变量读取问题。竞争力评分仅用于排名与事件固定选项排序。

### 4.2 角色域变量

| 变量 | 挂在谁身上 | 用途 |
|---|---|---|
| `ftr_claim_strength` | 参与角逐者 | 竞争力评分 |
| `ftr_court_backer_of` | 支持者 | 我支持谁（站队记账） |
| **`ftr_court_claimants`** | **最高统治者** | **参与角逐者列表（主存储）** |
| **`ftr_court_supporters`** | **权贵（君主/共治者/参与者）** | **各权贵的支持者列表（主存储）** |
| `ftr_court_owes_council` | **承诺者** | 欠下的内阁席位笔数（0016/0017 触发依据） |
| `ftr_court_promise_council` / `ftr_court_promise_contract` | **被承诺者** | 承诺类型 |
| `ftr_court_promised_by` | **被承诺者** | 谁向我承诺过 |
| `ftr_court_temp_duchy` | 起兵者 | 临时公国引用（战后回收） |

> 记账约定：**站队记在支持者身上（`ftr_court_backer_of`），支持者名单记在被支持权贵身上（`ftr_court_supporters`）**——前者标识支持关系，后者作为主存储供 GUI 直接读取。承诺记在被承诺者身上。支持者数直接用 `list_size:ftr_court_supporters` 计算，君主与共治者也各有支持者列表。

### 4.3 角色 flag

| flag | 时限 | 用途 |
|---|---|---|
| **`ftr_court_participating`** | 故事存续期 | **选择参与角逐**（可寻求/被支持） |
| **`ftr_court_declined_contest`** | **终身** | **明确不参与**（防止被他人主动支持） |
| `ftr_court_asked_participation` | 刷新清除 | 已被询问参与（防骚扰） |
| `ftr_court_cooldown` | 5 年 | 危机结算后冷却 |
| `ftr_court_disinherited` | 永久 | 已被剥夺继承权 |
| `ftr_court_assisted_this_year` | 1 年 | 今年已辅政 |
| `ftr_court_asked_stance` | 3 年 | 已被询问站队（防骚扰） |
| `ftr_court_asked_to_rebel` | 3 年 | 已被询问起兵（防骚扰） |
| `ftr_court_asked_usurp` | 3 年 | 已被询问废黜（防骚扰） |
| `ftr_court_purged` | 事件内临时 | 0011.b 清算标记（免债处理，用毕移除） |

### 4.4 竞争力评分（议题 1 的排名依据）

**不使用真实继承顺位**。原版无任何「顺位序号」触发器（`heir_order` / `succession_position` / `inheritance_order` 全库 0 命中），只有 `every_heir` 集合遍历。故改用**竞争力评分**排名：

`ftr_court_claim_strength_value` 构成（系数集中在 `ftr_court_struggle_values.txt`）：

| 维度 | 分值 |
|---|---|
| 年龄 | 成年 +20，青壮年(16–45) +10，老年 −10 |
| 能力 | 五维平均值 × 2 |
| 特质 | ambitious +30、genius +20、brave +10；content −30、craven −20、incapable −100、lunatic −25 等 |
| 实力身份 | 有地 +25、内阁 +15、共治者 +40、配偶 +10、法定继承人 +25 |
| 君主好感 | ≥50 → +15；≥0 → +5；<0 → −10 |
| 支持者 | 每人 +5 |

最终 `max = 0` 防负分。该评分对**主动选择参与角逐的继任者**计算，用于竞争者排序（如危机脉冲选头目、事件 0015 选择劝说对象）。

> 选举制与均分继承制下「顺位」本就模糊，评分反而更贴合玩家直觉。

## 5. 议题 2：共治夺权

### 5.1 权力天平（`ftr_court_regency_swing`）

| 值 | 含义 |
|---|---|
| −100 | 君权稳固（区间下限） |
| −40 | 触发「辅政稳固」判定 |
| 0 | 中性 |
| +40 | 触发「共治请愿」门槛 |
| +75 | 触发「废黜昏君」窗口 |

**变动来源汇总**（所有路径最终都经过 `ftr_court_shift_swing_effect`，该效果按 `ftr_court_swing_amount` 移动并夹紧区间）：

| 来源 | 幅度 | 说明 |
|---|---|---|
| 辅政交互（`assist_monarch`） | −8 | 有地权臣尽心王事 |
| 游说·劝忠（`lobby`） | −8 | 封臣互劝效忠君主 |
| 游说·劝进（`lobby`） | +8 | 封臣互劝支持共治 |
| 请愿获准（事件 0020.a） | +8 | 君主允诺共治 |
| 年度自然回落 | ±5 | 向 0 回归，防单向锁死 |
| 君主失能年度偏置 | +4/年 | 年老体衰或精神异常 |
| 君主强势年度偏置 | −4/年 | 声望充足 |

### 5.2 政治承诺（筹码机制）

许诺类交互（许官位 / 许宽免）在 `on_accept` 时建立双端记账（见 §4.2），继承后兑现：

**内阁席位 —— 三段式兑现链**：

```
许诺（记账：承诺者 owes_council +1；被承诺者记 promise_council + promised_by）
    │
继位（双路径全覆盖）
    ├─ 夺位 → usurp effect 尾部安排提醒
    └─ 自然继承 → on_death 检查 scope:primary_heir 欠账
    │
0016 首次提醒（继承后 3-7 日随机延迟 ← 错开多笔承诺，避免密集弹窗）
    ├─ a. 立刻授予 → 按最高技能实授 → 清账 → 若还有欠账串行下一个（5-15 日间隔）
    └─ b. 推迟一次 → 180-360 日随机延迟 → 0017
                        ├─ a. 授予 → 清账 → 串行
                        └─ b. 完全拒绝 → 背信好感 + 新君声望 −150 → 清账 → 串行
```

- **实授**：复用官方 `assign_appropriate_councillor_position_effect`（首选职位按最高技能，四级 fallback，现任可解雇检查）；非封臣承诺对象先 `add_courtier` 拉入宫廷
- **防呆**：0016/0017 均有欠账存在性检查——欠账已被其它途径兑现则事件**静默取消**；推迟不销账，只有授予/拒绝清账 → 结构上杜绝无限推迟；0017 无推迟选项
- **债务继承**：新君继承**存活者**的承诺。若旧竞争者在清算中被尽数处决，其生前许下的承诺一并作废（见 §8 事件 0011.b）

**契约放宽**：由 `ftr_court_fulfill_promises_effect` 以 `ftr_court_promised_contract_modifier` 兑现。该效果仅在清算事件 0011.a（赦免兑现）被调用——**新君选择清算或留地监视时契约承诺不自动兑现**。

### 5.3 夺位路径（议题 2 的三处出口）

| 路径 | 入口 | 适用 |
|---|---|---|
| **宫廷政变（0018.a）** | 天平 ≥ +75 且君主失能 → 危机脉冲询问朝堂最强势力（按兵力排序）→ 立即 `ftr_court_usurp_throne_effect`（夺位 + 囚禁 + 0010 清算链） | 全政体；**无需战争** |
| **密谋政变（0015.b）** | 危机脉冲询问竞争者 → `start_scheme = coup`（ftr 的 coup scheme） | **不限政体**（coup 密谋不要求领地，是无地 / 封建制有地竞争者的共同夺位路径；发起者须为君主朝堂成员以满足 coup `valid`） |
| **内战（0012.a / 0015.a）** | 竞争者起兵 → CB `ftr_succession_war` | 全政体；无地者先建临时公国（§6.2） |

**usurp 效果统一收尾**（`ftr_court_usurp_throne_effect`，两条夺位路径共用）：夺取主头衔 → 囚禁旧君 → 排清算事件 0010 → 安排内阁承诺提醒 → 新君冷却 5 年 → 朝堂通报「大位易主」→ **旧君名下 story `end_story`**（旧君尚存但已失位，story 不会自行转移；新君是否重启角逐由下一年度准入检查判定）。

## 6. 战争：继位内战

### 6.1 CB 设计（`ftr_succession_war`，组 `ftr_civil_war`）

| 参数 | 取值 | 说明 |
|---|---|---|
| `target_titles` | `none` | 目标是整个政权而非某个头衔 |
| `landless_attacker_needs_armies` | `no` | 无地皇子不会因无兵自动判负 |
| `ai_only_against_liege` | `yes` | 仅封臣对宗主 |
| **`white_peace_possible`** | **`no`** | **造反不能白和平（§6.4）** |
| `on_primary_attacker_death` | `inherit_faction` | 主攻方死亡后阵营不崩盘 |
| `cost` | 威望 350 | 发动门槛 |
| `allowed_against_character` | 封臣对宗主 **或** 无地同宗持临时公国 | 无地者不是封臣，需第二分支 |

### 6.2 临时公国（无地竞争者）

**关键认知：无地角色无法宣战。** `landless_attacker_needs_armies = no` 只解决"宣战后无兵自动判负"，不解决"宣战入口不存在"。因此临时公国必须在**宣战之前**创建。

**两段式创建时机**：

| 阶段 | 位置 | 说明 |
|---|---|---|
| **预建（主路径）** | `ftr_court_prepare_rebellion_effect`（事件 0012.a / 0015.a 调用） | 无地者先建临时公国 → 立即 `start_war`，一体完成 |
| 兜底 | CB `on_declaration` | 仅当无地且未预建时补建，防路径遗漏 |

创建内容（`ftr_court_create_temp_duchy_effect`）：`create_dynamic_title`（tier = duchy，名 `FTR_COURT_TEMP_DUCHY_NAME`）→ `set_landless_title` / `set_destroy_on_succession` / `set_delete_on_destroy` / `set_no_automatic_claims` → 首都取王国境内随机伯爵领 → `change_title_holder` → 记入 `ftr_court_temp_duchy`。

**回收**：`on_victory` / `on_defeat` / `on_white_peace` / `on_invalidated` **四处全部销毁**，不论战争结果；另有 story 清理兜底扫描。

### 6.3 支持者响应

站队时记 `ftr_court_backer_of`，宣战时自动召集（均以 `is_participant_in_war` 查重）：

- **叛乱方**：`ftr_court_call_backers_to_war_effect` → 站队对象 = 起兵者且有地者 → `add_attacker`
- **保皇派**：`ftr_court_call_loyalists_to_war_effect` → 未站队或站队对象非起兵者、且对君主好感 ≥ 0 → `add_defender`

### 6.4 造反不能白和平（核心规则）

**叛乱只有三种结局：胜、败、战争失效。不存在「打完握手言和」。**

| 结局 | 处理 |
|---|---|
| **胜利** `on_victory` | `ftr_court_usurp_throne_effect`（夺位 + 囚禁 + 清算链 0010→0011→0012 + 冷却 + 收场） |
| **失败** `on_defeat` | 剥夺继承权 + 声望 −300 / 虔诚 −100 + **双向停战 1825 天** + 事件 0013（君主定夺：终身监禁 / 流放 / 处死 / 宽恕）；君主侧加 5 年冷却 |
| **失效** `on_invalidated` | 仅回收临时头衔，不追究（失效多为目标死亡等意外） |
| ~~白和平~~ | 不可达。`on_white_peace` 保留为**安全兜底**：万一引擎异常路径触发，按失败同等代价处理 |

> **设计意图**：叛乱是押上性命的豪赌。允许白和平会让「看形势不妙就收兵」成为无风险策略，继位之争将退化为例行公事。
> **已知副作用（接受）**：内战打到一方彻底崩溃为止，可能使国家长期虚弱——这是叛乱应有的代价。

## 12. 方案优化蓝图（待确认开发）

> **定位说明**：本章是「烈度 + 每 60-120 天内斗循环 + 缓和决议」新机制的完整设计蓝图。
> 本章为**待确认的演进方案**，尚未开发。当前已实现系统（前述 §2–§11）仍为现状。
> 经需求澄清，已确定如下关键决策（见下文各小节）：
> - **内斗循环与现有脉冲的关系** = 原有内容**融入**新机制（非简单并存，是重构融合）。
> - **烈度承接** = `ftr_court_struggle_intensity`（0–200）替代 `ftr_court_phase`（0–3）判定；保留 0015/0018 等政变·内战出口，触发条件由 phase 改为 intensity 阈值（如达 150+ 触发）。
> - **竞争手段** = 全新独立事件系列（每种手段一个事件族），与现有事件并行，各自触发竞争者间的对抗。
> - **竞争者范围** = 在 story 中决定参与角逐者；若存在共治者且其有继承权，则共治者**被动参与**（纳入可被攻击 / 可被推翻的目标）。
> - **政变夺位路径** = 政变类夺位统一走 **ftr 的 `coup` scheme**（`common/schemes/scheme_types/ftr_coup_scheme.txt`），不再自造夺位逻辑；**起兵 / 内战仍走战争出口**（`ftr_succession_war`）。`ftr_court_struggle.0015.b` 已走 coup 且**已取消政体限制（封建制亦可用）**。

### 12.1 设计目标与核心转向

现状：story 以离散 `phase`(0–3) + 稀疏年度脉冲（8%/14%/20%）驱动，事件密度低、局面切换生硬，多为「通知—玩家被动观看」，缺少竞争者主动互相倾轧的博弈。

新方案转向**连续烈度驱动 + 高频内斗**：

1. 用连续值 `var:ftr_court_struggle_intensity`（0–200）替代离散 `var:ftr_court_phase`（0–3）。烈度越高，竞争者间的对抗手段越激烈，越逼近政变 / 内战。
2. 新增**每 60–120 天随机触发**的内斗循环 `ftr_court_internal_strife_on_action`：每次按概率**随机择一**竞争者主动出手，手段随烈度升级，且**保留不触发概率**。
3. 原由 phase 驱动的「危机 / 对立 / 潜伏脉冲」内容（0001/0003/0005/0014/0015/0018 等）**融入**新机制——不再按离散阶段各自独立滚动，而是统一由烈度区间决定手段池与出手强度。
4. 给最高统治者新增**缓和内部矛盾**决议：降低烈度 + 缓和与竞争者关系，冷却 10 年、高成本。

### 12.2 竞争者范围（已澄清）

`竞争者`（被内斗手段选中、或被攻击 / 被支持 / 可被推翻的对象）精确范围：

| 对象 | 是否竞争者 | 依据 |
|---|---|---|
| 主动参与角逐的继任者（`ftr_court_participating`，在 `ftr_court_claimants` 列表） | ✅ 主动竞争者 | 事件 0040 自愿参与 |
| 最高统治者（story owner） | ✅ 主动竞争者 | 既是中立方也是被夺权目标 |
| 共治者（diarch）**且**拥有继承权 | ✅ **被动竞争者** | 一旦有继承权即被拖入权力角逐，可被攻击/被支持/被推翻 |
| 共治者无继承权 | ⚠ 仅作为势力头目 | 参与共治夺权（议题 2），但不进入继位竞争者名单 |
| 已明确不参与者（`ftr_court_declined_contest`） | ❌ | 终身排除 |

> 内斗手段的攻击对象随机落在「其它竞争者 / 最高统治者 / 共治者（有继承权）」，攻击成功后推高烈度，形成竞争对抗闭环。

### 12.3 烈度系统（替代 phase）

#### 12.3.1 烈度含义与区间

`var:ftr_court_struggle_intensity` 范围 **0–200**（默认起点 0，事件 0040 有人参与后随内斗上升）：

| 区间 | 命名 | 局面定性 | 对应手段池强度 |
|---|---|---|---|
| 0–40 | 平静 / 潜伏 | 竞争暗藏、尚无公开冲突 | 极低烈度：流言、试探 |
| 40–90 | 酝酿 | 竞争者开始结党、拉拢支持 | 低烈度：诋毁、收买 |
| 90–140 | 对立 | 公开倾轧、势均力敌 | 中烈度：诬陷、下毒、制造牵制 |
| 140–170 | 濒危 | 剑拔弩张、随时擦枪走火 | 高烈度：绑架、谋杀、政变酝酿 |
| 170–200 | 临界 | 局面一触即发 | 政变 / 内战出口开启（最强手段） |

> 原 `ftr_court_phase` 的 0–3 语义（dormant/simmering/contested/crisis）被烈度区间覆盖；`ftr_court_update_phase_effect` 等阶段判定脚本随重构废除，由烈度维护脚本取代。

#### 12.3.2 烈度驱动源（进入新机制后）

烈度不由单一因素线性累积，而是**由内斗手段的成功与局势失衡共同推高**：

- 每一起内斗手段成功 → 按其烈度等级上调（如低 +5~10、中 +15~25、高 +30~50）。
- 君主状态（衰弱 / 失能 / 声望低）→ 上调当前烈度偏置（承接原 `ftr_court_monarch_weak_trigger` 语义）。
- 竞争者支持者差距悬殊或前两名评分接近 → 烈度上调（承接原 `ftr_court_is_contested_trigger` 语义）。
- 年度自然回落（向 0 缓慢回归），避免烈度单向锁死不回落。
- 缓和决议成功 → 大幅下调（见 §12.5）。

#### 12.3.3 烈度 → 政变 / 内战承接（已澄清）

**保留现有政变·内战出口**（0012 / 0015 / 0018 及其结算链 0010/0011），但触发条件由 `phase=3 crisis` **改为烈度阈值**：

| 出口 | 现触发条件 | 新触发条件（烈度化） |
|---|---|---|
| 竞争者政变（0015.b / 手段 2.7） | phase=3 危机脉冲推送竞争力最高者 | 烈度 ≥ 140 时内斗循环推送；**统一走 ftr 的 coup scheme**（`start_scheme { type = coup }`） |
| 竞争者起兵 / 内战（0015.a / 0012.a） | phase=3 危机脉冲推送竞争力最高者 | 烈度 ≥ 140 时内斗循环推送；仍走**战争出口**（`ftr_court_prepare_rebellion_effect` + `ftr_succession_war`） |
| 废黜昏君（0018 宫廷政变） | 天平 ≥ +75 且君主失能 | 烈度 ≥ 170（临界）且君主失能 → 推送朝堂最强势力（现状为借共治之权 `ftr_court_usurp_throne_effect` 直接夺位，属独立废黜出口，是否并入 coup scheme 留待实现权衡） |
| 清算链 / 再起兵（0010→0011→0012） | 由上述出口连锁 | 不变（出口结果后处理） |

> 原则：**烈度是"压力"（是否濒临爆点），权力天平 `ftr_court_regency_swing` 仍负责"方向"（议题 2 谁得势）**。二者解耦但叠加影响内斗手段的选择。

### 12.4 内斗循环（每 60–120 天）

#### 12.4.1 调度

新增 story 上 effect_group（或独立 on_action 依赖 story 存在性）：间隔 **60–120 天随机**，等价替代/吸收原「参与者询问刷新」之外的稀疏年度脉冲，成为**竞争推进主时钟**。

```
effect_group { days = { ftr_court_strife_min_value  ftr_court_strife_max_value }  # 60-120
    triggered_effect {
        trigger = { story_owner ?= { ftr_court_struggle_valid_trigger = yes } }
        effect  = { ftr_court_internal_strife_pulse_effect = yes }   # 见 §12.4.2
    }
    fallback = { end_story = yes }
}
```

> 原「危机 / 对立 / 潜伏」三组稀疏脉冲（8%/14%/20% 每年）**并入此高频循环**：其事件内容（0001/0003/0005/0014/0015/0018）改为由内斗循环按烈度区间与概率**择机派发**，不再各自独立以年为单位滚动。

#### 12.4.2 内斗手段矩阵（全新事件系列，与现有事件并行）

每次循环：先判定**是否出手**（保留不触发概率，如 base 随烈度变化：低烈度常静默、高烈度常出手），出手则**随机择一手段**，并随机选**发起竞争者**与**攻击对象**。手段如下（烈度越高手越辣）：

| # | 手段 | 类型 | 适用的烈度 | 针对目标 | 事件族（全新，`ftr_court_struggle.005x`） | 结局影响 |
|---|---|---|---|---|---|---|
| 2.1 | **诋毁 / 伪造证据 / 诬陷 / 下毒** | 事件链（口舌→物证→下毒逐级升级） | 40–140 | 其它竞争者 | `ftr_court_struggle.0050+`（多步骤链） | 可毁其声望 / 支持者流失 / 直接毒害；成功推高烈度 |
| 2.2 | **派间谍总管调查**（向上） | 君主反制手段 | 90+（对立后） | 君主揭发竞争者 | `ftr_court_struggle.006x` | 可压制发起者（效仿原 0005.c 压制） |
| 2.3 | **制造牵制** | 事件 | 90+ | 其它竞争者 / 权贵 | `ftr_court_struggle.007x` | 获得可要挟筹码 |
| 2.4 | **绑架** | 事件/计谋入口 | 140+ | 竞争者 / 君主 | `ftr_court_struggle.008x` | 短暂囚禁、逼退或逼和 |
| 2.5 | **谋杀** | 计谋入口（murder scheme） | 140+ | 竞争者 | `ftr_court_struggle.009x` | 直接清场；暴露则烈度更高 |
| 2.6 | **推翻共治者阴谋** | 事件 + 共治夺权联动 | 90+（有继承权共治者） | 共治者 | `ftr_court_struggle.00Ax` | 动摇共治、夺其势 |
| 2.7 | **继承顺位靠后者宫廷政变** | 政变入口（走 **ftr 的 coup scheme**） | 140+（政变走 coup；起兵走战争，见 §12.3.3） | 君主 | `00B0` → `start_scheme { type = coup }` / `ftr_court_prepare_rebellion_effect` | 政变夺位 |
| 2.8 | **选举制下收买 / 牵制有投票权臣属** | 事件 | 90+（选举继承） | 有投票权臣属 | `ftr_court_struggle.00Bx` | 拉票、锁定胜局 |

> **设计要点**：
> - 手段 2.1（诬陷下毒链）是最具代表性的长链，展示"低烈度先造口舌、烈度升级后再动真格"。
> - 手段 2.2 是君主对竞争者进攻的**反制**，让玩家在高烈度时也能主动破局（不仅被动看戏）。
> - 手段 2.7 / 2.8 直接挂到 §12.3.3 的政变出口或选举投票机制，避免与现有出口重复造轮。
> - **所有手段成功均有概率推高烈度**；烈度越高，循环越容易择中更强手段，从而更快逼近政变 / 内战——形成"积怨—升级—爆发"节奏。

### 12.5 最高统治者「缓和内部矛盾」决议

给最高统治者（story owner，独立统治者 / 王国级）新增决议，作为**对烈度的主动刹车**：

| 项 | 取值 |
|---|---|
| 决议 id | `ftr_court_ease_struggle_decision`（新，`ftr_` 前缀） |
| 冷却 | **10 年**（`cooldown`） |
| 成本 | 高额双轨成本：双方行政制消耗大量官方影响力，任一方非行政制消耗大量威望 |

> 设计意图：给玩家（君主位）一条**主动管理烈度**的路径，避免烈度只涨不降导致必爆。10 年冷却保证不能反复无限压火。

### 12.9 待定项（开发前确认）

### 12.10 手段事件族事件规格（事件 / 事件链 / 选项 / AI 倾向）

> 本节给内斗 8 类手段的**事件层规格**（概要）。命名空间沿用 `ftr_court_struggle`；新事件 ID 从 `0050` 起顺排，避免与既有 0001–0041 冲突。
> 事件触发一律遵循既有约束：`character_event`；无地廷臣只能被事件路径选中（不可主动发起交互）。
> 求值域：内斗循环在 **story 域**派发，派发给具体竞争者时必须包进 `story_owner`（当 root 需为角色时），或对目标直接 `trigger_event`（对齐 0015/0018 既有做法）。
> 事件文本双语文案新增内容加 `<FTR>`；AI 倾向统一用 `ai_chance`（事件）内 `base + modifier`（特质 / 属性 / 好感驱动），对齐本项目事件惯例。
> **立绘动作约定**：每个事件必须给 `left_portrait` / `right_portrait` 补**合适的 `animation`** 以增强代入感。动作取值见文档 06 §7 与项目 coup/combat_guide 事件：如 `happiness`、`rage`、`shock`、`scheme`、`fear`、`anger`、`beg`、`personality_rational`、`personality_bold` 等；涉及政变 / 密谋的发起方用 `scheme`、被夺位者用 `shock`/`fear`、上位者用 `personality_bold`。
> 状态：**既有 16 个事件（`ftr_court_struggle_events.txt` 的 0001–0041）已全部补上 portrait `animation`**（见代码，改动随本轮提交）。

#### 12.10.3 手段事件链总规则

- **事件链**（2.1a→b→c 诬陷下毒链；2.6 共治夺权链）逐级升级：下级事件只在烈度升入新区间且玩家/对象仍存活时由循环续推。
- **政变 / 谋杀 / 起兵**等强手段走**官方机制**：政变夺位 → **ftr 的 `coup` scheme**（`start_scheme { type = coup }`）；谋杀 → **官方 murder scheme**（`start_scheme { type = murder }`）；举旗 → **战争出口**（`ftr_court_prepare_rebellion_effect`）。事件只负责**发起入口**与**结果加工**，不自己模拟底层判定。
- 事件**成功与否**由「选项 + 既有触发/计谋判定」决定；成功即按 §12.3.2 推高烈度。
- **防骚扰 / 防叠砸**：发起竞争者与目标各打短期 flag（`ftr_court_strife_active` / `ftr_court_targeted`），循环派发前过滤掉近期待触发者。
