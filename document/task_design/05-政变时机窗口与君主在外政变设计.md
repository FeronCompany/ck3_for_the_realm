## 1. 目标与范围

### 1.1 设计目标

现有 `coup` 计谋只有三条入口（角色交互、`ftr_court_struggle.0140.b`、`0160.a`），且事件入口全部绑死朝堂烈度（≥140 / ≥170）。本设计补两项能力：

1. **时机窗口**：政变不再只由烈度驱动，改由「君主处于虚弱时机」驱动——每类时机一个专属征询事件，由潜在发起者自行决定是否动手；
2. **君主在外政变链**：政变对象随君主位置变化——君主不在首都时，夺取对象由「君主本人」变为「中枢」，可以**矫诏遥控废君**，被废君主转为**无地冒险者**。

### 1.2 需求总览

| # | 需求 | 本文件章节 |
|---|---|---|
| 1 | 时机窗口按**时机类型分别派发不同事件**，事件主角自决是否发起政变 | §2 |
| 2 | 君主在外时政变改为「夺中枢 → 矫诏废君」，君主转无地冒险者 | §3 |
| 3 | 新增政变中途事件，降低重复性 | §4 |
| 4 | 目标侧（君主）通知事件补齐既有空壳 | §3.5 |

### 1.3 范围与硬约束

| 项 | 口径 |
|---|---|
| 生效政体 | 不限。时机窗口只要求政权存在朝堂 story（`ftr_court_struggle`，即独立且主头衔 ≥ 王国） |
| 生效对象 | 时机窗口标记挂在**君主**（story owner）身上；征询事件推给**朝堂参与者名单**（`ftr_court_participant_list`）中的在世、成年、在主君朝中者 |
| 复用优先 | 篡位结算复用现有 `ftr_coup_success_effect` 的头衔转移段；无地化复用原版 `set_landless_government_effect` + `create_landless_adventurer_title_effect`；征询复用 `ftr_court_coup_pull_backers_effect` |
| DLC 依赖 | 「转无地冒险者」依赖 `roads_to_power`（EP3）。无该 DLC 时走兜底（保留无地状态，不转政府形态），效果与提示均以守卫包裹 |
| 不可触碰 | 原版所有文件；新增一律 `ftr_` 前缀 |

## 2. 时机窗口系统

### 2.1 时机类型与窗口标记

窗口标记是**挂在君主（story owner）身上的角色 flag**，带时长。只要标记在身，该时机的征询事件就可能被派发。

| 时机类型 | flag | 设置方式 | 检测条件 | 时长 |
|---|---|---|---|---|
| 君主离城 | `ftr_coup_window_travel` | 主时钟轮询 | `ftr_coup_monarch_away_trigger`（见 §3.1） | 180 天 |
| 新君即位 | `ftr_coup_window_newreign` | `on_title_gain` 钩子 | 权力交接类 transfer（继承 / 篡夺 / 废立） | 2 年 |
| 君主失能 | `ftr_coup_window_infirm` | 主时钟轮询 | `is_incapable = yes` | 365 天 |
| 君主被囚 | `ftr_coup_window_imprisoned` | 主时钟轮询 | `is_imprisoned = yes` | 365 天 |
| 君主被绝罚 | `ftr_coup_window_excommunicated` | 主时钟轮询 | `is_excommunicated = yes` | 2 年 |

> 状态型（离城 / 失能 / 被囚 / 被绝罚）由轮询续期，条件消失后 flag 自然到期；即位型由钩子一次性设置，不续期。

### 2.2 刷新与派发

在 `ftr_court_struggle` story 新增一个 `effect_group`（周期 `ftr_coup_window_refresh_months_value` = 2 个月）：

```
effect_group {
	months = ftr_coup_window_refresh_months_value
	triggered_effect = {
		trigger = { story_owner ?= { ftr_court_struggle_valid_trigger = yes } }
		effect = {
			ftr_coup_window_refresh_effect = yes     # 续期/设置五类标记
			ftr_coup_window_dispatch_effect = yes    # 按类型概率派发征询
		}
	}
	fallback = { ftr_court_end_story_if_owner_deposed_effect = yes }
}
```

- `ftr_coup_window_refresh_effect`：求值域 = story；逐个检查条件并 `add_character_flag` 续期。
- `ftr_coup_window_dispatch_effect`：求值域 = story；对五类标记各调一次 `ftr_coup_window_dispatch_one_effect`。
- `ftr_coup_window_dispatch_one_effect`：参数 `FLAG`（标记名）、`CHANCE`（概率 %）、`EVENT`（事件 ID）。命中则从参与者名单随机取一名合格候选（`ftr_coup_window_candidate_valid_trigger`），推 `EVENT`。
- 候选若已在政变中、或在冷却（`ftr_coup_window_ask_cooldown`）中则跳过。

### 2.4 发动加成

窗口事件中选择「立即发动」时，给发起者写 `var:ftr_coup_opening_bonus`（值 = 该时机加成，`days = 365`），并叠加其身上已存在的 `ftr_coup_lie_low` 奖励。`coup` 计谋的 `base_success_chance` 读取该变量并追加为成功率修正 `FTR_COUP_OPENING`。

「隐忍待机」写 `ftr_coup_lie_low`（`days = 730`），自身不加成，仅提高下次窗口的发动加成。

中途事件（§4）同样通过 `ftr_coup_add_opening_bonus_effect` 累加该变量——「时机窗口 + 中途事件」的加成是叠加关系。

### 2.5 征询事件（`ftr_court_struggle.0170-0174`）

root = 候选参与者。每个事件 immediate 定位君主（封臣走 `top_liege`、廷臣走 `employer`）与朝堂 story，并给出该时机的专属画像与描述。

| 事件 ID | 时机 | 选项 |
|---|---|---|
| `0170` | 君主离城 | a 就是现在（发动）/ b 按兵不动（隐忍）/ c 静观其变 |
| `0171` | 新君即位 | 同上三选项 |
| `0172` | 君主失能 | 同上三选项 |
| `0173` | 君主被囚 | 同上三选项 |
| `0174` | 君主被绝罚 | 同上三选项 |

选项 a：「立即发动」→ `start_scheme { type = coup }` + `ftr_court_coup_pull_backers_effect` + 写发动加成 + 写冷却。
选项 b：「隐忍」→ 写 `ftr_coup_lie_low` + 写冷却。
选项 c：「静观」→ 仅写冷却。

## 3. 「君主在外」政变链

### 3.1 君主在外判定

脚本条件 `ftr_coup_monarch_away_trigger`（root = 目标君主）：

```
OR = {
	is_travelling = yes
	is_leading_army = yes
	AND = {
		exists = capital_province
		NOT = { location = capital_province }
	}
}
```

任一成立即视为「不在中枢」。

### 3.2 结算分流

`ftr_coup_outcoming.4000`（结算）在成功且未提早暴露时，追加一层分流：

- 目标**不在中枢** → 走新 on_action `ftr_coup_success_away`；
- 目标**在都** → 走现有 `ftr_coup_success`（擒获 + 篡位）。

失败分支不变（现有 `ftr_coup_failure`）。

### 3.3 矫诏篡位效果

现有 `ftr_coup_success_effect` 拆为两段：

| effect | 职责 |
|---|---|
| `ftr_coup_transfer_realm_effect` | 头衔转移 + 封臣改宗 + 宫廷宏伟度继承（原步骤 3-8），擒获与否两条链共用 |
| `ftr_coup_success_effect` | 从龙功/好感 → **擒获目标** → 合法性损失与恐惧 → 调用 `ftr_coup_transfer_realm_effect` |
| `ftr_coup_away_success_effect` | 从龙功/好感 → **不擒获** → 合法性损失与恐惧 → 调用 `ftr_coup_transfer_realm_effect` → **目标转无地冒险者** |

目标转无地冒险者（DLC 守卫）：

```
if = {
	limit = { has_dlc_feature = roads_to_power }
	scope:target = {
		set_landless_government_effect = yes
		create_landless_adventurer_title_effect = {
			REASON = flag:deposition
			FLAVOR_CHAR = scope:owner
		}
		create_landless_adventurer_title_tooltip_effect = yes
		adventurer_prestige_reset_effect = yes
	}
}
```

无该 DLC 时只保留「失去全部头衔」的无地状态（不改变政府形态）。

### 3.4 结果事件（`ftr_coup_outcoming.1010-1012`）

按 `var:ftr_coup_method`（0 强攻 / 1 潜入 / 2 陷阱）分三支，镜像现有 `1000-1002`：

| 事件 ID | method | 选项 |
|---|---|---|
| `1010` | 0（或未设） | a 逐其流亡（默认）/ b 令其消失（`unknown_murder_effect`） |
| `1011` | 1 | 同上 |
| `1012` | 2 | 同上 |

immediate 统一：通知目标 `3010` → `ftr_coup_away_success_effect` → `end_scheme`。

选项 a「逐其流亡」不含额外效果（无地化已在 `ftr_coup_away_success_effect` 内完成）。
选项 b「令其消失」调用 `unknown_murder_effect { VICTIM = scope:target  MURDERER = root  REASON = death_disappearance }`。

### 3.5 目标侧通知（`ftr_coup_outcoming.3010`）

君主在外时得知政变。画像 shock，效果为空（仅通报），与既有 `3000-3005` 同构。

### 3.6 on_action

`common/on_action/schemes/ftr_coup_on_actions.txt` 新增：

```
ftr_coup_success_away = {
	events = {
		ftr_coup_outcoming.1010
		ftr_coup_outcoming.1011
		ftr_coup_outcoming.1012
	}
	on_actions = { ftr_clear_coup_variable_effect }
}
```

### 3.7 AI 收口（直接触发结算）

**原版 follow-up 不是引擎自动触发的**：它由 `scheme_critical_moments` 选项内的效果**显式**发出——
`scheme_critical_moments_events.txt`：`trigger_event = { saved_event_id = scope:follow_up_event }`。
因此 `follow_up_event`（本 mod = `ftr_coup_outcoming.4000`）只有在玩家/AI **选中 `0001`/`0002` 的某个选项**时才会发出。

而 `0002` 各选项的 `trigger` 均含 `scope:scheme = { scheme_agent_charges >= multi_ending_scheme_charge_to_advance_threshold_tX_value }`。
政变是短链条、攒不到 agent charges，AI 选不出任何可用项 → follow-up 永不发出 → **卡在满成功率不结算**。
仅补 `on_semiyearly` 重推准备事件不足以解决：事件推出来了，选项仍不可用。

**本 mod 口径**：`coup` 的结果由 `scheme_success_chance` + `var:ftr_coup_method` 完全决定，不需要原版「择定收口方式」这一步。故：

| 挂载 | 作用 |
|---|---|
| `on_phase_completed` | 压住 follow-up → `ftr_coup_scheme_prep_effect`（存 `scheme`/`owner`/`target` 与 `follow_up_event`）→ **AI 且成功率 ≥ 50 时直接 `trigger_event = ftr_coup_outcoming.4000`** |
| `on_hud_click` | 玩家路径：重推准备事件，玩家自行择定收口 |
| `on_semiyearly` | 兜底：AI 政变若相位久未走完，tick 时同样直接触发结算（自行 `save_scope_as` 存好三个 scope） |

```
on_phase_completed = {
	suppress_scheme_follow_up_event_till_input_given_effect = yes
	ftr_coup_scheme_prep_effect = yes
	cap_schemes_and_fire_reminders_effect = yes
	if = {
		limit = {
			scheme_owner = { is_ai = yes }
			scheme_success_chance >= 50
		}
		scheme_owner = { trigger_event = ftr_coup_outcoming.4000 }
	}
}

on_semiyearly = {
	if = {
		limit = {
			scheme_owner = { is_ai = yes }
			scheme_success_chance >= 50
		}
		save_scope_as = scheme
		scheme_owner = { save_scope_as = owner }
		scheme_target_character = { save_scope_as = target }
		scheme_owner = { trigger_event = ftr_coup_outcoming.4000 }
	}
}
```

- 成功率门槛 `50` 与 `0002` 的 AI 判定同口径，避免 AI 在胜算过低时硬发动。
- 触发前必须已存在 `scope:scheme` / `scope:owner` / `scope:target`（由 `prep` 或本块自行 `save_scope_as` 提供），否则 `4000` 内的作用域取值为空。
- `on_phase_completed` 路径下 `suppress_next_event` 已在身，故 `prep` 不会对 AI 弹出准备事件；`on_semiyearly` 路径刻意不复用 `prep`，同样避免弹出。
- 玩家仍可在相位完成前从计谋面板手动择定收口（`on_hud_click`）。

## 4. 政变中途事件（`ftr_coup_ongoing.1010-1015`）

新增六个中途事件，挂 `ftr_coup_ongoing` 权重表。它们与现有 `1000-1009` 的区别：**面向「控制中枢」而非「准备强攻」**，在君主在外时收益最大。

| 事件 ID | 标题 | 触发条件 | 选项与效果 |
|---|---|---|---|
| `1010` | 封锁驿道 | 无 | a 封锁要道（`ftr_coup_add_opening_bonus_effect` +8） / b 不必多事 |
| `1011` | 挟持摄政 | 无 | a 拉拢（+12） / b 胁迫（60% 得 +18，否则压力） / c 不必理会 |
| `1012` | 矫诏 | 无 | a 伪造诏令（+10） / b 不屑伪造 |
| `1013` | 夺武库、控宫门 | 无 | a 夺占（+15） / b 按兵不动 |
| `1014` | 百官劝进 | 无 | a 私下走动（+10） / b 让朝臣自行归心 |
| `1015` | 称病待机 | 无 | a 称病不出（压力−） / b 继续推进（+5，压力+） |
