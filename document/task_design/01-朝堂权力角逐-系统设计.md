# 朝堂权力角逐（Court Struggle）系统设计

> 本文件是「朝堂权力角逐」系统的**唯一设计出处**。
> **修改任何相关脚本代码前先读本文件，改完代码后必须同步更新本文件。**
>
> 对应议题：议题 1（继任者之争）、议题 2（共治夺权）。
> 议题 3（异族异教）、议题 4（对外战争）已移出本次范围，未实现。

---

## 1. 目标与范围

### 1.1 设计目标

在**独立王国 / 帝国 / 霸权**级别政权内部，模拟一场围绕大位的持续权力角逐：

- **议题 1 — 继任者之争**：多名继任竞争者以「竞争力评分」排名，取前五名进入朝堂名单，彼此排挤、拉拢支持者；势均力敌时可能爆发政变或内战。
- **议题 2 — 共治夺权**：君主因年老体衰或精神异常而不能正常履职时，权臣与潜在继任者尝试获取共治权力乃至夺取大位；保皇派与拥立派围绕「权力天平」拉锯，双方以官位、契约为筹码争取支持者。

### 1.2 适用范围（准入条件）

由 `ftr_court_struggle_valid_trigger` 统一判定，三条必须同时满足：

| 条件 | 实现 |
|---|---|
| 独立政权 | `is_independent_ruler = yes` |
| 等级 ≥ 王国 | `highest_held_title_tier >= tier_kingdom` |
| 存在继承顺位 | `any_heir = { always = yes }` |

附加限制：`is_ruler = yes`、未被囚禁、非战时、不在冷却期内。

### 1.3 触发入口

**以最高统治者为唯一触发入口。** Story cycle 的 `owner` 恒为在位君主。

其他身份（竞争者、权臣、普通封臣）通过交互与决议**参与**，或完全不参与、只旁观系统推送的事件。所有交互/决议的 `is_shown` 均以君主为视角组织，非君主角色看到的是自己能做的那一小部分。

## 2. 技术选型：为什么用故事循环，不用局势

| 方案 | 结论 | 理由 |
|---|---|---|
| **局势 Situation** | ❌ 否决 | `sub_regions` 必须绑定**静态地理区域**（`geographical_regions`，上限 255 且不可重叠）。而需求是「每个独立王国各自内部」的权力斗争——王国边界会变、会灭亡、全球同时存在几十个。局势无法按政治实体开实例。中原王朝循环能用，是因为它是全地图唯一且绑死在中国地区。 |
| **故事循环 Story Cycle** | ✅ 采用 | 绑角色（`owner` = 君主）、可多实例（owner 维度隔离 → 全球每个王国各持一个实例）、`on_owner_death` 天然对应「君主驾崩重洗牌」、`visualization` 原生支持角色名单与拉锯条。 |
| **纯脚本状态机** | ❌ 否决 | 无原生面板，需自建 GUI；无生命周期管理，清理易泄漏。 |

### 2.1 关键接口（原版实测确认）

| 用途 | 接口 |
|---|---|
| 启动故事 | `create_story = <key>`（角色域执行，owner = 当前角色） |
| 结束故事 | `end_story = yes` |
| 防重复 | `any_owned_story = { type = <key> }` |
| 排序遍历列表 | `ordered_in_list = { list = X  order_by = <script value> }` |
| 列表长度 | `list_size:<list_name>`（用于 `set_variable`） |
| 无地头衔 | `create_dynamic_title` + `set_landless_title` + `set_delete_on_destroy` |
| 剥夺继承权 | `disinherit_effect = { DISINHERITOR = scope:X }`（在**被剥夺者**域执行） |
| 停战协定 | `add_truce_both_ways = { character = X  days = N  war = W  result = R }` |
| 宣战 | `start_war = { casus_belli = X  target = Y }` |
| 拉人入战 | `scope:war = { add_attacker / add_defender = scope:X }` |

> ⚠ **已修正的文档错误**：`document/09-故事循环与局势.md` 与 `document/16` 中原写作 `start_story = { }`，**原版不存在此 effect**，正确写法是 `create_story = <key>`。

## 3. 系统架构

单一 story cycle 类型 `ftr_court_struggle`，挂在最高统治者身上，内含两个可独立开关的子议题。

```
ftr_court_struggle (story cycle, owner = 最高统治者)
├── on_setup        初始化变量、建立候选人池
├── effect_group A  年度维护：刷新候选池、拉锯自然回落、阶段迁移
├── effect_group B  危机脉冲（20%/年）
├── effect_group C  对立脉冲（14%/年）
├── effect_group D  潜伏脉冲（8%/两年）
├── on_owner_death  驾崩 → end_story（清理统一交给 on_end）
├── on_end          清理临时头衔、清除变量与 flag
│
├── 子议题 1：继任之争（ftr_court_succession_struggle_active）
│   └── 阶段：dormant → simmering → contested → crisis
└── 子议题 2：共治夺权（ftr_court_regency_struggle_active）
    └── 以 ftr_court_regency_swing 为拉锯轴
```

**为何用两个开关变量而非两个 story cycle 类型**：两个议题共享同一个朝堂参与者池与政治影响力资源，拆成两个容器会导致数据同步困难与面板割裂。

### 3.1 阶段定义（`var:ftr_court_phase`）

| 值 | 阶段 | 判定条件 |
|---|---|---|
| 0 | dormant | 竞争者数 < 2 |
| 1 | simmering | 竞争者数 ≥ 2 |
| 2 | contested | 前两名评分差 ≤ `ftr_court_contested_gap_value`(20) |
| 3 | crisis | 评分差 ≤ `ftr_court_crisis_gap_value`(8) **且** 君主衰弱 |

阶段由 `ftr_court_update_phase_effect` 统一定档，供图标切换、脉冲分派、可视化使用。

## 4. 数据模型

### 4.1 故事域变量（挂在 story 上）

| 变量 | 类型 | 用途 |
|---|---|---|
| `ftr_court_phase` | int | 0–3 阶段号 |
| `ftr_court_candidate_count` | int | 竞争者人数 |
| `ftr_court_candidate_pool` | char list | 全部候选人的**工作池**（用于排序） |
| `ftr_court_claimant_list` | char list | 前五名（**喂给面板 `character_list`**） |
| `ftr_court_top_score` / `ftr_court_second_score` | int | 前两名分数 |
| `ftr_court_top_gap` | int | 前两名分差（阶段判定依据） |
| `ftr_court_regency_swing` | int | 权力天平（−100 君权稳固 / +100 共治得势） |

### 4.2 角色域变量

| 变量 | 用途 |
|---|---|
| `ftr_claim_strength` | 候选人竞争力评分 |
| `ftr_court_backer_of` | 我支持谁（站队记账，记在**支持者**身上） |
| `ftr_court_backer_count` | 该候选人获得的支持者数 |
| `ftr_court_promised_by` | 谁向我承诺过（记在**被承诺者**身上） |
| `ftr_court_promise_council` | 承诺类型：内阁席位 |
| `ftr_court_promise_contract` | 承诺类型：契约放宽 |
| `ftr_court_temp_duchy` | 临时公国引用（战后回收） |

### 4.3 角色 flag

| flag | 用途 | 时限 |
|---|---|---|
| `ftr_court_pooled` | 候选池去重标记 | 重建池时清除 |
| `ftr_court_cooldown` | 危机结算后冷却 | `ftr_court_cooldown_years_value`(5) 年 |
| `ftr_court_disinherited` | 已被剥夺继承权（防重复） | 永久 |
| `ftr_court_assisted_this_year` | 今年已辅政 | 1 年 |

### 4.4 竞争力评分

**不使用真实继承顺位。** 原版无任何「顺位序号」触发器（`heir_order` / `succession_position` / `inheritance_order` 全库 0 命中），只有 `every_heir` 集合遍历。因此改用**竞争力评分排名**：

`ftr_court_claim_strength_value` 构成（全部系数集中在 `ftr_court_struggle_values.txt`）：

- **年龄**：成年 +20，青壮年(16–45) +10，老年 −10
- **能力**：五维平均值 × 2
- **特质**：ambitious +30、genius +20、brave +10；content −30、craven −20、incapable −100、lunatic −25…
- **实力身份**：有地 +25、内阁成员 +15、共治者 +40、配偶 +10、法定继承人 +25
- **人望**：君主好感 ≥50 → +15；≥0 → +5；<0 → −10
- **支持者**：每人 +5
- 最终 `max = 0`，避免出现负分

> 选举制与均分继承制下「顺位」本就模糊，评分反而更贴合玩家直觉。

候选人来源：君主的 `every_heir` + `every_child` + `every_sibling`，经 `ftr_court_claimant_valid_trigger` 过滤（存活、成年、未被囚禁、非 incapable、同宗族、非修道者）。

## 5. 议题 2：共治夺权

### 5.1 权力天平（`ftr_court_regency_swing`）

| 值 | 含义 |
|---|---|
| −100 | 君权稳固 |
| −40 | 触发「辅政成功」判定 |
| 0 | 中性 |
| +40 | 触发「共治请愿」门槛 |
| +75 | 触发「夺位」门槛 |

**年度动态**（`ftr_court_swing_yearly_effect`）：
- 向 0 自然回落 ±5，避免单向累积锁死
- 君主失能（incapable / lunatic / 高龄）→ 每年 +4 向共治者倾斜
- 君主声望充足 → 每年 −4 向君主倾斜

**单次站队**：支持共治者 +8，支持君主 −8。

### 5.2 筹码机制

新增两档**政治承诺**：

| 承诺 | 记账 | 兑现 |
|---|---|---|
| 内阁席位 | `ftr_court_promise_council = 1` | 上位后由 `ftr_court_fulfill_promises_effect` 结算 |
| 契约放宽 | `ftr_court_promise_contract = 1` | 同上（当前以 `ftr_court_promised_contract_modifier` 兑现） |

> ⚠ **已知缺口**：内阁席位的实授（`appoint_councillor` / `give_council_position`）接口尚未验证，当前以功臣好感替代，代码中留了 TODO。

### 5.3 资源与成本（双轨制，核心约定）

**Mod 自带的 `ftr_political_influence` 已废弃**（该概念早于官方行政制实践，官方 1.16 起自带影响力货币）。本系统所有资源支付一律走**双轨制**：

| 情形 | 支付货币 |
|---|---|
| 双方均为行政制（`government_allows = administrative`） | 官方影响力 `influence` |
| 任一方非行政制 | 威望 `prestige` |

**实现**（一对宏参数化接口）：

| 接口 | 作用 |
|---|---|
| `ftr_court_can_pay_cost_trigger`（triggers） | 支付能力判定。参数：`OTHER`（对方）、`PRESTIGE`、`INFLUENCE`（正数成本常量） |
| `ftr_court_pay_cost_effect`（effects） | 实际支付，按上表分流。参数同上 |
| `ftr_court_grant_favor_effect`（effects） | 恩宠双轨发放（事件 0001.c 君主示好）。参数：`TARGET` |

**成本常量分设两组**（影响力稀缺、威望量大，量级不同，见 `ftr_court_struggle_values.txt` §六）：

| 交互 | 威望 | 影响力 |
|---|---|---|
| 公开表态支持 | 120 | 40 |
| 倒戈改投 | 75 | 25 |
| 尽心辅政 | 90 | 30 |
| 许以内阁席位 | 180 | 60 |
| 许以宽免义务 | 150 | 50 |
| 奏请共治 | 240 | 80 |

> 影响力成本对照官方量级（minor 30 / medium 60 / major 100 / massive 150）：单次交互落在 minor~massive 区间；恩宠走官方 `minor_influence_gain`（30）。

**设计动机**：行政制角色自有一套影响力经济，本系统若坚持 mod 自铸货币会与之并存冲突；而非行政制玩法（封建/氏族等）完全没有影响力概念，必须回退到威望。双轨制让两种政体下的成本体感一致。

### 5.4 夺位路径

1. 权臣通过 `ftr_court_petition_coregency_interaction` 奏请共治 → 事件 0020 由君主裁决
2. 拉锯达 +75 且君主失能 → `ftr_court_can_attempt_usurp_trigger`
3. 夺位执行：`ftr_court_usurp_throne_effect` → 夺取主头衔 + 囚禁老君王 → 事件 0010

## 6. 战争：继位内战

### 6.1 CB 设计

| 参数 | 取值 | 理由 |
|---|---|---|
| `group` | `ftr_civil_war`（新建） | 避免污染原版 `civil_war` 组 |
| `target_titles` | `none` | 目标是整个政权而非某个头衔 |
| `landless_attacker_needs_armies` | `no` | 无地皇子不会因无兵自动判负 |
| `ai_only_against_liege` | `yes` | 仅封臣对宗主 |
| **`white_peace_possible`** | **`no`** | **造反不能白和平，见 §6.4** |
| `on_primary_attacker_death` | `inherit_faction` | 主攻方死亡后阵营不崩盘 |

### 6.2 临时公国（无地竞争者）

无地的廷臣皇子/王子起兵时，`on_declaration` 中为其创建**纯虚拟临时公国**：

```
create_dynamic_title = { tier = duchy  name = FTR_COURT_TEMP_DUCHY_NAME }
→ set_landless_title = yes         # 无地头衔
→ set_destroy_on_succession = yes  # 不传承
→ set_delete_on_destroy = yes      # 销毁即彻底删除
→ set_no_automatic_claims = yes    # 不留宣称
→ set_capital_county = <王国境内随机伯爵领>
→ change_title_holder + resolve_title_and_vassal_change
→ 记入 var:ftr_court_temp_duchy 以便回收
```

**回收策略**：`on_victory` / `on_defeat` / `on_white_peace` / `on_invalidated` **四处全部销毁**，不论战争结果。另有年度兜底扫描（在 `ftr_court_cleanup_effect` 中）防止异常路径泄漏。

### 6.3 支持者响应

站队时记 `ftr_court_backer_of`，宣战时自动召集：

- **叛乱方**：`ftr_court_call_backers_to_war_effect` 遍历君主的 `every_vassal`，凡站队对象 = 起兵者且有地 → `add_attacker`
- **保皇派**：`ftr_court_call_loyalists_to_war_effect` 遍历 `every_vassal`，未站队或站队对象非起兵者且对君主好感 ≥0 → `add_defender`
- 两者均用 `is_participant_in_war` 查重

### 6.4 造反不能白和平（核心规则）

**叛乱只有三种结局：胜、败、战争失效。不存在「打完握手言和」。**

| 结局 | 处理 |
|---|---|
| **胜利** `on_victory` | 夺位 + 囚禁老君王 → 事件链 0010 → 0011 → 0012（决定老君王与其余竞争者命运） |
| **失败** `on_defeat` | 剥夺继承权 + 声望重罚 + 双向停战 + 事件 0013（君主处置叛乱者） |
| **失效** `on_invalidated` | 仅回收临时头衔，不加惩罚（失效多为目标死亡等意外） |
| ~~白和平~~ | `white_peace_possible = no`，**不可达**。`on_white_peace` 保留为安全兜底，施加与失败同等惩罚，防止引擎异常路径让叛乱者全身而退 |

**失败的具体代价**（`on_defeat`）：

1. `disinherit_effect = { DISINHERITOR = scope:defender }` —— 造过反的人不配再排队
2. 声望损失 `ftr_court_rebellion_prestige_loss_value`
3. `add_truce_both_ways`（并计入 `ftr_court_cooldown`），防止立刻再来一次
4. 事件 0013 交由君主定夺：终身监禁 / 流放 / 处死 / 宽恕

> **设计意图**：叛乱是押上性命的豪赌。允许白和平会让「看形势不妙就收兵」成为无风险策略，继位之争将退化为例行公事。禁止白和平之后，发起叛乱前必须真正掂量胜算。
>
> **副作用（已知并接受）**：内战会打到一方彻底崩溃为止，可能使国家长期虚弱。这被视为叛乱应有的代价。

## 7. 交互与决议

### 7.1 交互（`ftr_court_interactions.txt`）

| 交互 | 议题 | 作用 |
|---|---|---|
| `ftr_court_back_claimant_interaction` | 1 | 公开表态支持某竞争者（其余竞争者记恨） |
| `ftr_court_withdraw_backing_interaction` | 1 | 撤回支持，重归中立 |
| `ftr_court_defect_interaction` | 1 | 倒戈改投（旧主记恨） |
| `ftr_court_assist_monarch_interaction` | 2 | 辅政，拉锯向君主一侧移动 |
| `ftr_court_petition_coregency_interaction` | 2 | 奏请共治 |
| `ftr_court_promise_council_seat_interaction` | 2 | 许以内阁席位 |
| `ftr_court_promise_contract_relief_interaction` | 2 | 许以宽免义务 |

### 7.2 决议（`ftr_court_decisions.txt`，均以君主为入口）

| 决议 | 作用 | 冷却 |
|---|---|---|
| `ftr_court_nominate_heir_decision` | 事件 0030 挑选继承人，抬高其评分、压低其余 | 5 年 |
| `ftr_court_consolidate_authority_decision` | 拉锯向君主一侧移动 | 2 年 |
| `ftr_court_suppress_claimant_decision` | 事件 0031 挑选对象，削其评分与支持者 | 3 年 |

> **为何用事件而非决议直接选人**：CK3 决议无法动态指定目标角色。所有「点名某个人」的操作一律转成事件，用 `ftr_court_save_ranked_claimants_effect` 把前五名存为 `scope:ftr_court_claimant_1~5`，再以固定选项呈现。

## 8. 事件

| ID | root | 说明 |
|---|---|---|
| 0001 | 君主 | 潜伏期：暗流涌动 |
| 0003 | 君主 | 对立期：势均力敌 |
| 0005 | 君主 | 危机期：一触即发 |
| **0010** | 新君 | **老君王的命运**：软禁 / 地牢 / 处决 |
| **0011** | 新君 | **其余竞争者**：赦免兑现 / 尽数清算 / 留地监视 |
| **0012** | 竞争者 | **臣服或再起兵**：可 `start_war` 用同一 CB 讨伐新君 |
| **0013** | 君主 | **处置叛乱者**（造反失败后）：终身监禁 / 流放 / 处死 / 宽恕 |
| 0020 | 君主 | 裁决共治请愿 |
| 0030 | 君主 | 册立储君（选前五名之一） |
| 0031 | 君主 | 压制竞争者（选前五名之一） |

**夺位清算链**：`0010 → 0011 → 0012`。新君先定老君王，再定其余竞争者，最后握有领地军队的竞争者可选择起兵再战。

> 事件触发点：story 的 `effect_group` 内必须写成 `owner = { trigger_event = ... }`，因为 `trigger_event` 的 root 取当前作用域，而事件是 `character_event`；直接调用会让 root 变成故事本体。

## 9. 频率控制

| 层级 | 手段 | 值 |
|---|---|---|
| 准入 | 独立 + ≥王国 + 有继承顺位 + 非战时 + 非冷却 | 排除绝大多数领地 |
| 休眠 | dormant 阶段不产生事件 | 零开销 |
| 潜伏脉冲 | 每 2 年 | 8% |
| 对立脉冲 | 每年 | 14% |
