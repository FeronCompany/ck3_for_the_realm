> 本文是对 CK3 原版「共治（Diarchy / 共治者）」系统的完整逆向整理，作为后续扩展设计（优化篡位机制、强化太子/共治者等）的**基线资料**。

> - 资料来源：`game/common/diarchies/**`、`game/common/character_interactions/00_diarch_interactions.txt`、`game/common/scripted_triggers|effects|values`、`game/common/on_action/diarchy_on_action.txt`、`game/common/decisions/00_diarchy_decisions.txt`、`game/common/schemes/scheme_types/diarch_schemes.txt`、`game/events/diarchy_events/*`、`game/events/education_and_childhood/coming_of_age_events.txt`。
> - 行号以当前安装版本（CK3 1.19.\*，含 Roads to Power 与「天朝/大秘书处」等后续内容）为准；未来上游更新可能移位，阅读时以对象名为准。
> - 前置阅读：[13 政体、特质与共治（第三章共治）](13-政体、特质与共治.md)、[10 法律与继承](10-法律与继承.md)、[15 common 目录清单与速查表](15-common目录清单与速查表.md)。
> - 术语：**Liege 主君 / Diarch 共治者（副手）**；diarchy 表示这一对关系。

## 1. 共治是什么

**共治 = 一个统治者（主君）与一名共治者（副手）分享治理的安排。**

三个语义家族：

| 家族 | 原版文件 | 特点 |
|---|---|---|
| 摄政（Regency） | `diarchy_types/00_regencies.txt` | 副手**暂时**持有权威以协助主君，事后应归还 |
| 共治（Co-rulership） | `diarchy_types/00_co_rulerships.txt` | 副手**永久**持有权威（终身助手 / 提前授权的继承人） |
| 首相府（Primeministership） | `diarchy_types/00_primeministerships.txt` | 副手**半永久**代理治理，权威仍源于主君委任 |

关键机制一句话：

```
引擎每月把 power swing（0-100）按 DIARCHY_MONTHLY_POWER_CHANGE 拉向 swing_balance
   → swing ≥ 某 power_level.swing → 解锁该层 parameter
   → 脚本用 has_diarchy_active_parameter 检查「某个权力是否生效」
```

**权力天平（scales of power / swing）是共治唯一的权限开关。**

## 3. 引擎硬编码 API（脚本中无定义、被直接调用）

这是做扩展最重要的挂点。**以下关键字在脚本目录中没有定义**，属于引擎保留，只能使用不能改写。

| 类别 | 关键字 | 说明 |
|---|---|---|
| 效果 | `try_start_diarchy = <type>` | 尝试建立指定类型共治（`faction_demands`、任命交互等） |
| 效果 | `set_diarch = <角色>` | 设定当前共治者；惯例紧跟 `try_start_diarchy` 使用 |
| 效果 | `end_diarchy = yes` | 结束共治（触发 on_left_diarchy） |
| 效果 | `set_diarchy_type = <type>` | 运行时更换共治类型（幼帝成年 → co_emperorship 即用它） |
| 效果 | `set_diarchy_swing` / `change_diarchy_swing` | 设 / 改天平数值 |
| 效果 | `set_diarchy_mandate = <mandate>` | 强制指派执政命令 |
| 效果 | `depose_diarch = yes` | 废黜共治者 |
| 值 | `diarchy_swing` | 当前天平读数（常与 `scope:...` 搭配） |
| 触发器 | `is_diarch` / `is_diarch_of_target = X` / `is_designated_diarch` / `is_diarch_valid_trigger` / `is_diarch_able_trigger` | 共治身份 / 候选人有效 |
| 触发器 | `has_active_diarchy` / `has_diarchy_type = <type>` | 是否存在共治 / 是什么类型 |
| 触发器 | `has_diarchy_parameter = <param>` | 查类型静态参数（type 层，不随 swing） |
| 触发器 | `has_diarchy_active_parameter = <param>` | 查**当前生效**的 power_level 参数（随 swing 解锁） |
| 触发器 | `has_active_mandate = yes` | 副手是否有执行中的命令 |
| 作用域/列表 | `liege.diarch`（现任副手）、`liege.designated_diarch`（候任）、`every_diarchy_succession_character` | 共治继任序列遍历 |
| 规则 | `is_diarch_valid` / `is_diarch_able` | 引擎回调到脚本触发器判定有效性（`00_diarchy_scripted_triggers.txt:22` 注释） |

> 惯用法：参数基本挂在**主君（共治所有者）**身上检查，如 `scope:actor.liege ?= { has_diarchy_active_parameter = xxx }`；副手侧常用 `has_active_mandate`、`diarch_loyalty`、`years_as_diarch` 等。

### defines 常量（`common/defines/00_defines.txt` 的 `NDiarchy` 块）

| 常量 | 值 | 含义 |
|---|---|---|
| `DIARCHY_SUCCESSION_SIZE` | 5 | 共治继任线人数（现任/候任占第一） |
| `DIARCHY_MONTHLY_POWER_CHANGE` | 0.25 | 天平每月向 swing_balance 趋近的量 |
| `DIARCH_APTITUDE_LEVELS` | { 20 40 60 80 } | 资质分档位切点 |
| `DESIGNATE_DIARCH_INTERVAL_DAYS` | 3650 | 指定/更换副手的冷却（约 10 年） |

## 4. 共治类型总览（8 种）

### 4.1 摄政（`00_regencies.txt`）

|---|---|---|---|---|---|---|

| 类型 | 行号 | 定位 | `succession` | swing 关键档 | `swing_balance` | `end_interaction` |

| 类型 | 行号 | 定位 | 关键档位 | `end_interaction` |
|---|---|---|---|---|

- 宰相副手：压力 +0.3、宗族威望 -0.25/月、按主君月结余与自身管理属性拿约 5%/5 管理的「俸禄与贪腐」（:124-146）。

### 4.4 类型通用结构字段（语法）

```paradox
key = {
	start = { ... }            # 共治建立时必须为真（原版内容型都用 always = yes）
	end = { ... }              # 为真即自动结束；空/always = no = 只能脚本结束
	succession = yes/no        # 是否启用「副手补选」机制（摄政/首相府 yes）
	candidate_score = { }      # 补选打分，root = 被评估候选人
	aptitude_score = { }       # 资质总分（可引用 mandate_type_qualification:<key>）
	loyalty_score = { }        # 忠诚分
	mandate = <type>           # 可多个，从中激活一个
	power_level = { swing = N  parameter = X ... }   # 可多个，阶梯解锁
	swing_balance = { }        # 天平每月趋近目标
	end_interation = <交互>     # 共治窗口里用于结束本类型的交互（_info 原文拼写如此）
	liege_modifier = { }       # 挂主君
	diarch_modifier = { }      # 挂副手（_info 里两处都写作 liege_modifier 系笔误）
}
```

## 5. 执政命令（Mandate）

`diarchy_mandates/00_mandates.txt` 定义 9 种。每个含两个脚本值：
- `qualification_score`：副手/候选人在该任务上的适任度（root = 副手或候选人）；
- `ai_score`：主君选择该命令的倾向。

原版命令与用途：

| 组 | 命令 | 核心属性 | 备注 |
|---|---|---|---|
| 标准三件套 | `fill_coffers`（充盈国库） | 管理为主，学识/密谋减半 | 摄政 / 共治 / 宰相通用 |
| | `swell_armies`（扩军） | 军事为主，勇武/外交减半 | 同上 |
| | `promote_authority`（提升权威） | 外交为主，军事/学识减半 | 同上 |
| 游牧假命令 | `ranching` / `horde_mustering` / `promote_obedience` | 见文件 :177 起 | 仅游牧摄政 |
| 天朝专用 | `placate_movements`（安抚运动）/ `promote_might`（彰武）/ `promote_merit`（扬贤） | 密谋/军事/功绩等 | 大秘书处专用；受三大臣头衔加成与 `var:diarch_forced_mandate` 强制 |

> 命令资格分带性格加成/减成（如 fill_coffers 偏好 arbitrary/callous、厌恶 generous/greedy），详见 `00_mandates.txt`。

## 7. 权限落地：共治者交互

`character_interactions/00_diarch_interactions.txt` 集中实现副手特权。典型对象与作用：

| 交互 | 作用 | 触发条件要点 |
|---|---|---|
| `diarch_syphon_treasury_interaction` | 搜刮共治国库 | 已解锁对应参数 |

## 8. 篡位手段（夺权链条）—— 重点

**核心结论：原版「副手推翻主君」不是计谋，而是「铺垫 → 决策 → 事件对决」链**，总开关是 `regents_can_try_to_overthrow_present_lieges`。

### 8.1 各类型解锁政变的 swing 门槛

| 类型 | 门槛 |
|---|---|
| `co_emperorship` | 80（副手皇帝最容易翻脸） |
| `regency` / `nomad_regency` / `co_monarchy` | 95 |
| `vizierate` / `grand_secretariat` | 90 |
| `temporary_regency` / `junior_emperorship` | 无该参数（后者靠成年转正路线） |

### 8.2 路线一：临时摄政 → 固化摄政
- 临时摄政 `swing_balance = 100`：拖得越久天平自动偏向副手；
- swing 100 解锁 `unlock_entrench_regency_interaction` → `diarch_entrench_regency_interaction` 把类型切成 `regency`，主君此后难以罢免。

### 8.3 路线二：固化摄政 → 自任共治皇帝（swing 80）
- `diarch_can_appoint_self_co_emperor` → `diarch_regent_appoints_self_co_emperor_interaction`：`set_diarchy_type = co_emperorship` 并把 swing 主动压低（把摄政权威兑现成共帝身份，从低位重新爬）。
- 同档含 `regency_cant_be_ended_above_this_point`：主君已无法正常结束共治。

### 8.4 路线三：核心政变——推翻领主、篡夺主头衔

入口对象：
1. 大决议 `diarch_attempt_to_overthrow_liege`（`00_diarchy_decisions.txt:11`；展示条件 = 你是主君的共治者 `is_diarch_of_target = liege` 或候任 `is_designated_diarch`）；
2. 拉拢交互 `diarch_coup_liege_interaction`（`00_diarch_interactions.txt:4984`）：对权势封臣密约政变，写 `coup_pv_supporters_list`（许诺分弱/强 hook、金、大金，见 `00_diarchy_scripted_effects.txt:96` 起的清点）；
3. 对峙事件 `diarchy.9001`（外交）/ `9011`（阴谋）/ `9021`（武力）及各自收尾（`diarchy_events.txt` :10263 / :10838 / :11445 起）；
4. AI 路径 `diarchy.9031 / 9032`（:12162 / :12361）。

合法性判定 `diarch_coup_attempt_is_valid_trigger`（`00_diarchy_scripted_triggers.txt:753`）逐条：

1. 你是现任共治者，且主君共治**激活**政变参数（`has_diarchy_active_parameter = regents_can_try_to_overthrow_present_lieges`）；
2. 主君必须在场可擒：未被囚、不旅行、不处战争、不处活动、年龄 ≥ 5；
3. **支持者达标**：`coup_pv_supporters_list` 中「主君的权势封臣或豪门家族」数量 ≥ `pv_overthrow_threshold_value`（拉拢过程中持续复核 `diarch_coup_valid_conspiracy_culmination_vassals_trigger`）；或已有 `laid_coup_groundwork_flag` 铺垫旗标可豁免人数；
4. 年限门槛：`years_as_diarch >= 8`，或 `years_as_diarch >= 4` 且主君 `years_in_diarchy >= 10`，或已有铺垫；
5. 主君 `sub_realm_size >= minor_realm_size`。

附加限制（`is_valid_showing_failures_only`，:800）：副手可用成人、未处单挑；主君最高级头衔里须有非教廷首脑头衔。宰相（vizierate）额外要求极高威望 + 与主君家族关系 `antagonistic`（决策 :64-74）。

发起后（决策 `random_list` 结果预览）：
- 主君认命 → 和平交权：副手拿走主君全部最高级头衔，境内「可拿」的王国头衔、法理首府与首府公爵领一并拿走；其余领地留给主君继续统治；
- 主君抵抗后落败 → 副手拿走更多头衔，主君可能失去一切；
- 外交线：胜 → 主君留命、副手被视为仁慈；败 → 副手被擒；
- 阴谋线：胜 → 主君被囚；败 → 副手被擒；
- 武力线：胜 → 主君死；败 → 副手死。

AI 侧：仅 `diarch_loyalty <= diarch_loyalty_visibly_disloyal_threshold`（明显不忠）的副手考虑政变，行动后打 `immune_ai_coups` 冷却旗标（`00_diarchy_scripted_effects.txt:96-215`）。

### 8.5 路线四：互残式终局 `systematically_maim_character_interaction`（共治三型的 end_interaction）
- 主君致残副手 → `clear_designated_heir + end_diarchy`：废掉既定继承人并解散共治，不流血；
- 副手致残主君 → `create_title_and_vassal_change type = usurped` 分两批改宗：第一批拿走最高级头衔、首府伯爵领+首府公爵领并收编全部封臣，第二批前主君沦为副手封臣，随后 `end_diarchy`（`00_diarchy_scripted_effects.txt:1620-1704`）。
- 含义：共治关系没有「和平罢免」出口，只能下狠手；这本身也保护副手不被随意踢走。

### 8.6 路线五：和平让渡 / 成年交接（太子向机制）
- `junior_emperorship` swing0 常驻：`diarch_is_preferred_liege_heir`、`diarchy_transition_into_co_emperorship_on_majority`、`half_sop_swing_transfer_over_on_majority`、`liege_may_voluntarily_cede_authority`；
- 成年转正 `junior_emperor_graduates_to_co_emperor_effect`（`coming_of_age_events.txt:3316`）+ 事件 `coming_of_age.3011`：`set_diarchy_type = co_emperorship`，**swing 对折移交（×0.5）**，并按转正时已解锁的 `diarch_gain_skill_on_majority_t1..t4` 给对应教育线的属性点。
  - **坑**：注释明言「必须留在旧类型直到最后一刻，否则参数全丢」——`set_diarchy_type` 会换掉整套 power_level 参数表，设计时勿在切换前依赖动态参数。

### 8.7 路线六：推翻摄政的计谋 `overthrow_regent`（方向相反）
- `diarch_schemes.txt:1`：`allow = { liege ?= diarch; this != liege.diarch }`，即**第三方**（觊觎摄政位者）对现任摄政开 hostile 计谋；
- 只能作用于摄政型（`scope:owner.liege ?= { has_diarchy_parameter = diarchy_is_regency }`），**不能推翻共治型**；
- 成功后把现任摄政替换成自己（`overthrow_regent_scheme_prep_effect` 推进）。

### 8.8 路线七：主君死亡后的自然交接
- 共治三型 `succession = no`：副手通常已被设为主君继承人，主君死亡即登基；
- 摄政/首相府 `succession = yes`：副手位置空出后，从 `DIARCHY_SUCCESSION_SIZE = 5` 的候选序列按 `candidate_score` 补选（摄政 `diarchy_regent_succession_score_value`、宰相 `diarchy_vizier_succession_score_value`）。

## 9. 开启方式与生命周期

- **任命交互**（`00_diarch_interactions.txt` 后半）：`appoint_junior_emperor_interaction`（:9617 附近）、`appoint_co_emperor_interaction`（:9849 附近）、`appoint_co_monarch_interaction`（:10075 附近），执行体均为标准两步 `try_start_diarchy = <type>` + `set_diarch = 目标`，随后必要时把副手设为既定继承人；更换副手有 10 年冷却。
- **其它启动源**：`declare_me_co_emperor_interaction`（`06_ep3_interactions.txt:10636`）、派系/事件驱动（`faction_demands` 等）。
- **自动巡检**：`on_action/diarchy_on_action.txt` 处理自动结束（如天朝大秘书处随 `title:h_china` 消失而 `end_diarchy`，:393-400）与候任指定后行为。
- **月度摆动**：引擎按 `DIARCHY_MONTHLY_POWER_CHANGE` 把 swing 拉向 `swing_balance`；脚本侧有 `update_diarchy_swing_with_perspective_effect` 封装「偏向谁」的文案与结算。
- **UI/播报**：共治窗口 `gui/diarchy_window*`；快捷按钮 `important_actions/00_diarchy_actions.txt`；消息 `messages/01_diarch_messages.txt`。

## 10. 与周边系统的接口

- **法律/继承**：`acclamation_succession_law` 约束幼帝/共帝存续；`may_appoint_co_monarchs_trigger`、政府 flag `may_appoint_viziers`、`government_is_celestial` / 三省法（grand_chancellor/grand_marshal/grand_censor_law）与 `e_minister_*` 头衔决定相应类型可用性与继任打分。
- **行政制**：副手在行政制帝位晋升上有 mild~massive 档加成；共帝特有「改组官僚」「索要 despotate」等行政制交互。
- **通用保护**：`00_prison_interactions.txt` 禁止对共治者公开敌对/监禁；`00_alliance.txt` 中副手一般只在内战响应征召；`grant_titles` 等会阻止把副手法理领地下封给他人。

## 11. 对扩展的点位小结

### 优化篡位方向的可调单点
- 政变解锁 swing 门槛（类型文件 power_level）、时间门槛（`years_as_diarch`）、支持者门槛 `pv_overthrow_threshold_value`、AI 参战线 `diarch_loyalty_visibly_disloyal_threshold`、冷却 `immune_ai_coups`、结局改宗范围（`maiming_destroy_diarchy_effect` / 政变事件的 title change 列表）。
- 现状缺口可补：副手专属「夺位计谋」（现有 `overthrow_regent` 方向相反）、夺位后的合法性/正统性叙事、少主阵营还政斗争、两位共治皇帝间内斗（`scapegoat_counterpart_interaction` 只是雏形）。

### 强化太子/共治者方向的可调单点
- `junior_emperorship` 0/20/40/60/80 档位参数、`swing_balance` 年龄曲线、成年转正时的 swing 对折与技能档、任命交互（`appoint_junior_emperor_interaction`）门槛、任期累进影响力 modifier——均可整体放权或增加交互。
- 也可参考本 mod 已有 `scheme/coup` 与故事循环实现，为太子补「提前亲政」「密谋反噬父皇」「太子监国」等专属玩法。

### 接入 mod 的命名约定
- 新增共治类型 / mandate / parameter 一律 `ftr_` 前缀（如 `ftr_<类型>`、`ftr_<mandate>`、`ftr_<param>`）；
- **覆盖原版对象**（如调整 `temporary_regency` / `regency` 的 power_level、swing_balance）须复制原版原文并保留改动外条目，用 `###### OVERRIDE ######` 包裹，勿加 `ftr_` 前缀；
- 文件路径对应：`common/diarchies/diarchy_types/ftr_*.txt`、`common/diarchies/diarchy_mandates/ftr_*.txt`；
- 涉及本地化时中英双语同步，新增用户可见文本加 `<FTR>`（参见 AGENTS.md）。
