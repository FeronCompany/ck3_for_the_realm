# 25 傀儡系统

> **1.20 新增**：统治者通过「傀儡」代行自己无法直接执行的行动。数据层在 `common/puppets/`，脚本层靠 `set_puppet` 与 `scope:puppet_or_actor`。

## 本篇导读

- **数据层**：`types/` 定义傀儡类型（含 `actions` 列表），`actions/` 把既有交互/决议/大工程包装成可代行动作。
- **脚本层**：`set_puppet` 建立关系、`has_puppet_type` 判定、`puppet:<类型>` / `puppeteer` 两个方向的作用域。
- **关键**：`scope:puppet_or_actor` 表示「实际发令者」，写可代行交互时必须用它取代 `scope:actor` 并做兜底初始化。

## 2.1 数据层（`common/puppets/`）

| 目录 / 文件 | 内容 |
|---|---|
| `types/*.txt` | 傀儡类型。字段：`interaction`（建立用交互）、`can_have`、`is_valid`（每日校验，失效则移除）、`priority`、`actions`、`asset`、`animation` |
| `actions/*.txt` | 傀儡动作。字段：`type`（`character_interaction` / `decision` / `great_project`）、`interaction` / `decision` / `great_project`（对应键）、`is_enabled`、`is_important` |

官方内置三种类型：`theological_agent_puppet`（本国神职代理）、`external_theological_agent_puppet`（外部神职统治者）、`external_ruler_puppet`（外部世俗统治者），各挂约 80 个 `puppet_action_*`。

> `_puppet_types.info` 原文关键句：*"The game does not set the puppet up automatically, you need to run `set_puppet` yourself in the interaction."*

## 2.2 脚本层 API

| 类别 | 写法 | 说明 |
|---|---|---|
| 效果 | `set_puppet = { target = <角色>  type = <傀儡类型> }` | 建立傀儡（引擎**不**自动建立） |
| 效果 | `clear_puppet_status = yes` | 解除（在**傀儡**身上执行；会切断 `puppeteer` 链接） |
| 效果 | `remove_puppet_modifiers_effect = yes` | 清理傀儡产生的修正 |
| 触发器 | `has_puppet_type = <傀儡类型>` | 该角色是否正充当某类型傀儡 |
| 触发器 | `exists = puppeteer` | 该角色是否**作为傀儡**存在操纵者 |
| 触发器 | `exists = puppet:<傀儡类型>` | 该角色是否**拥有**某类型傀儡 |
| scope | `puppet:<傀儡类型>` / `scope:puppet` | 操纵者 → 傀儡 |
| scope | `puppeteer` / `scope:puppeteer` | 傀儡 → 操纵者 |
| scope | `scope:puppet_or_actor` | **实际发令者**：有傀儡时为傀儡持有者，否则为 `scope:actor` |
| scope | `scope:is_puppet_action ?= yes` | 标记"本次交互由傀儡动作触发" |
| 概念 / GUI | 脚本名 `puppet_type`（本地化键 `game_concept_puppet_type`，alias `puppet_types`）、`gui/window_puppet_selection.gui` | UI |

## 2.3 写一个「可经傀儡代行」的交互

三件套：

1. 在 `common/puppets/actions/` 建 `puppet_action_*`，把 key 加进对应傀儡类型的 `actions` 列表；
2. 交互内以 **`scope:puppet_or_actor`** 取代 `scope:actor` 做"谁在发令"的判定，并加引擎兜底（GUI 可能未初始化该 scope）：

```paradox
# this not initalized in GUI
if = { limit = { NOT = { exists = scope:puppet_or_actor } }
	scope:actor = { save_temporary_scope_as = puppet_or_actor } }
```

3. 用 `scope:is_puppet_action ?= yes` 分流提示文案与冷却归属。

## 2.4 陷阱清单

- **必须自己 `set_puppet`** —— 引擎不会因 `actions` 列表而自动建立关系。
- **`clear_puppet_status` 会切断链接** —— 若后续还要用到 `puppeteer` / 傀儡，须**先** `save_scope_as` 存下再清（官方注释：*"Both scopes are saved up front because clear_puppet_status severs the puppeteer link"*）。
- **冷却记在操纵者身上** —— 傀儡动作的冷却跨该操纵者的**全部**傀儡共享。
- **`scope:puppet_or_actor` 不可直接假设存在** —— 必须写兜底初始化再使用。
- **一个 `puppet_action_*` 只应挂在一个傀儡类型上**（官方 `.info` 明示）。
- 傀儡被移除的时机不止交互：`on_action/death.txt`、`player_change_on_actions.txt`、`yearly_on_actions.txt` 都会清理，别在这些路径之外残留状态。
